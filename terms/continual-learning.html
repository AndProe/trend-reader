Continual learning

first seen 2026-W37 · 9 links · 3 min read

Today's models are trained once and then fixed. Everything they learn during use is lost when the session ends, unless the developer retrains the model at great cost. Continual learning would change that: a model that adjusts its own weights as it works, so that a lesson learned on Monday is still there on Friday and an agent that has operated a company's systems for a year is better at them than one that started yesterday. The obstacle is catastrophic forgetting. Small updates pile up and overwrite earlier knowledge, and no reliable method yet exists for many incremental updates without decay.

For an executive the term marks the boundary of what agents can currently do. Improvement over time today comes from context, memory files and prompts, not from the model itself, which is why agents feel capable but static. If continual learning is solved it becomes a central factor in recursive self-improvement debates and in how much a lab's models can diverge from a competitor's; until then, investment in the memory and harness layer is the practical substitute.

Also seen as online learning from deployment, lifelong learning

Deeper dive

How it works. Standard training happens in a large batch before release, followed by Post-training to shape behaviour, after which weights are frozen. Continual learning proposes ongoing updates from deployment data: user interactions, task outcomes, corrections. The technical difficulty is that gradient updates on new data disturb the representations that encode old knowledge. With a handful of updates this is manageable; with thousands of small ones the model drifts. Researchers debating the path to recursive self-improvement treat forgetting under many small updates as the open problem, distinct from the question of whether models can learn at all.

Why it matters now. Continual learning appears as one of four capability foundations in surveys of agentic systems, alongside perception, reasoning and coordination, because an agent that operates in a changing environment needs to adapt without a retraining cycle. It is closely tied to the debate on Recursive self-improvement: a system that cannot retain what it learns cannot compound gains. In the meantime, harnesses approximate it. Evidence that performance keeps improving across a million-token session, with step curves that continue to rise, shows that in-context learning can persist for a long time, but only until the session ends, and only within the limits set by Context rot. External memory, skill libraries and Persistent agents carry knowledge across sessions without touching weights.

Trade-offs. Updating weights in deployment raises safety and governance problems that frozen models avoid: a model that learns from users can be taught bad behaviour, drift away from its evaluated state, and become impossible to reproduce for audit. It also blurs the distinction between the vendor's model and the customer's data, since the customer's interactions become part of the weights. Test-time training and Test-time adaptation are narrower alternatives that adapt at inference time without permanent change, trading durability for control.

What to watch. Whether any lab ships a model that updates from deployment at scale, progress on forgetting-resistant update methods, and whether memory-based approaches at the harness level prove sufficient to make the weight-level problem less urgent.

Post-training

Post-training is everything done to a model after its initial pretraining on raw text: supervised fine-tuning, preference optimisation and reinforcement learning on tasks and environments.

Recursive self-improvement

Recursive self-improvement is the use of AI systems to accelerate the research, data, code and infrastructure that produce the next AI system, so that each generation shortens the time to the one after it.

14 linksconcept

Working memory

Working memory is an agent's capacity to hold and update task state across steps, whether kept in the model's context or externalised into files, logs and maps that the agent builds as it goes.

7 linkstechnique

Test-time adaptation

Test-time adaptation is the practice of adjusting an agent to a particular person, task or situation while it is being used, either through the context it holds or through small updates to its weights.

7 linksconcept

Persistent agents

Persistent agents are AI agents designed to run continuously and carry memory, identity and relationships across sessions, devices and tasks, instead of starting fresh on each request.

needed by 2 · 16 linksconcept

Context rot

Context rot is the degradation of an AI agent's performance and memory reliability as its conversation history accumulates, even when the total stays within the model's nominal context window.
