Mixture of experts

first seen 2026-W35 · 7 links · 3 min read

A mixture-of-experts model splits its feed-forward layers into many expert blocks and adds a router that sends each token to a few of them. The model's total parameter count is large, which gives it knowledge and capability, but the compute per token is that of a much smaller model. GLM 5.3 Flash has 320 billion parameters in total and 18 billion active per token; a recent DeepSeek release runs 552 billion total with 8 to 16 billion active.

For an executive the architecture explains the price collapse in capable models. It lets a lab ship a model that competes with closed frontier systems on many tasks while charging a fraction of the serving cost, and it is why open-weights models are a credible procurement option. The cost sits in memory: all the experts must be stored even though few are used, so serving demands large, fast memory and careful placement rather than raw compute, and the choice of hosting provider matters more than with dense models.

Also seen as MoE, sparse experts

Deeper dive

How it works. In a dense transformer every parameter participates in every token. In a mixture-of-experts model the feed-forward block in each layer is replaced by a set of experts and a learned router that assigns each token to the top few by score. Only those experts run, so compute per token scales with active parameters while capacity scales with total parameters. Training must balance the load across experts, or a few experts absorb everything and the rest are wasted. At inference the difficulty moves to data movement: the router's choice determines which weights must be resident, which tensors must stay close together, and where reuse between tokens can be exploited. Serving stacks map experts across devices and memory tiers, and recent work on offloading embedding tables to SSD shows that such interventions can change expert selection, which is a reminder that routing is sensitive to the surrounding system.

Why it matters now. The architecture is the mechanism behind cheap, capable Open weights models. GLM 5.3 Flash at 320 billion total and 18 billion active parameters, and DeepSeek V4.1 Flash with several hundred billion total and a small active slice, deliver near-frontier results at a serving cost closer to a Small language models tier. Some researchers count it as a scaling-enabling innovation in its own right rather than a mere efficiency trick, because it lets total capacity grow without proportional compute. Token efficiency improves for the same reason: each token costs less, so longer reasoning becomes affordable.

Trade-offs. Memory is the price. All experts must be stored, so a 320-billion-parameter model needs the memory of a 320-billion-parameter model even though it computes like an 18-billion one, which favours hosts with abundant HBM or good offloading. Routing adds latency and can be unstable under distribution shift. Combining the architecture with Sparse attention compounds the systems complexity, since both change what must be resident when. Quality per active parameter also lags a dense model of the same active size on some tasks.

What to watch. Active-to-total parameter ratios in new releases, hardware designed around expert placement and memory tiering, and whether closed frontier models disclose their own use of the architecture.

Related terms

concept

Open weights models

Open weights models are AI models whose trained parameters are published for anyone to download, run and modify, in contrast to closed models reachable only through a vendor's API.

needed by 11 · 36 linksmetric

Token efficiency

Token efficiency is the amount of useful capability a model delivers per token consumed or produced, whether measured as output tokens per task, accuracy per token, or the input-to-output ratio of a workload.

9 linkstechnique

Sparse attention

Sparse attention is a family of attention mechanisms in which each token attends to a selected subset of positions rather than to every previous token, so that the cost of long contexts grows less than quadratically.

6 linksconcept

Small language models

Small language models are models designed to be small from the start, typically from around one to fourteen billion parameters, rather than large models compressed after training.

DeepSeek V4.1 Flash is DeepSeek's open-weights model that benchmarks level with Claude Opus 5 and GPT-5.6 Sol, the previous frontier generation.
