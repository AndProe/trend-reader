Agentic inference workloads

first seen 2026-W35 · needed by 1 · 16 links · 3 min read

A chat request is one prompt and one answer. An agent on a task makes dozens or hundreds of model calls, each carrying the whole history so far, pausing while it runs tests or reads files, and sometimes spawning several parallel agents. Most of each request repeats the previous one, so the serving system can reuse cached computation if it keeps the cache available. Agents also consume CPU, because they compile, test and lint between model calls, one reported driver of CPU shortages.

This changes what to buy and what to benchmark. Hardware should be evaluated on agent traffic rather than chat traffic; on that basis, new rack-scale systems are claimed to deliver very large gains in performance per dollar, and the question of whether an incumbent vendor's software advantage holds is being tested on exactly these workloads. Cost per task depends on cache reuse and memory as much as raw compute, and infrastructure plans need CPU and memory budgets that chat-era assumptions omit.

Also seen as agentic traffic, agent serving, multi-turn long-context serving

Deeper dive

How it works. Four features define the pattern. Multi-turn: an agent task is a long sequence of calls, each appending new observations to the same conversation. Long context: the conversation grows toward the model's limit, at which point it is compacted and continues. High prefix reuse: consecutive calls share almost all their tokens, so the KV cache from one call serves the next if it is retained, and because turns are separated by pauses while tools run, it is worth offloading that cache to DRAM or storage rather than holding it in expensive accelerator memory. Sub-agent bursts: a coordinator may spawn several Sub-agents at once, producing spikes of parallel demand. Serving designs respond with Prefill-decode disaggregation, tiered cache offloading and admission logic that keeps tool containers and accelerators busy.

Why it matters now. Benchmarks built on replayed agent traces, including compaction near the context limit, have become the standard on which accelerator vendors, cloud providers and custom chips are compared, and results differ sharply from chat benchmarks: the rack-scale systems that keep large caches close to compute show much larger gains in performance per dollar, and the CUDA moat question is being argued on agent traffic specifically. On the cost side, Cost per task for agent work depends on cache hit rates and memory more than on per-token price, and enterprises measuring Enterprise agent tokens find consumption dominated by repeated context. Repeated evaluation of an evolving agent is itself a standing workload of this type.

Trade-offs. Cache offloading trades memory cost for latency and complexity, and stale caches after the underlying documents change need repair. Optimising for throughput on long agent runs conflicts with the interactivity users expect from chat, the Interactivity versus throughput tension. Agents' CPU consumption for tool execution is easy to overlook and now shows up as shortages and rising CPU pricing. And because agent traffic is bursty, capacity planned for average load will queue at exactly the moments agents are most useful.

What to watch. Whether agent-trace benchmarks displace chat throughput as the headline metric in vendor claims. Whether memory and cache capacity, rather than accelerator count, become the binding constraint on agent serving. And whether serving prices begin to reflect cache reuse explicitly, which would change how agent products are priced to end customers.

concept

AI agents

Software systems in which a language model plans, calls tools and acts over many steps toward a goal rather than answering a single prompt.

needed by 20 · 33 linksconcept

Long context

Long context refers to model context windows of hundreds of thousands to a million tokens, which allow an agent or a user to place entire codebases, document collections or multi-hour recordings in front of the model at once.

needed by 4 · 12 linkstechnique

KV cache

The KV cache is the per-token store of key and value vectors that a transformer keeps during generation so it does not recompute attention over the whole context on every step.

needed by 2 · 12 linkstechnique

Prefill-decode disaggregation

Prefill-decode disaggregation is a serving architecture that processes a request's prompt on one pool of hardware and generates its output tokens on another, transferring the KV cache between them.

6 linkstechnique

Sub-agents

Sub-agents are parallel agents spawned inside a single run under a coordinator, each given a slice of the task and its own context, with results returned to the parent.

needed by 1 · 13 linksmetric

Cost per task

Cost per task is the dollar cost of getting a unit of work actually completed by an AI system, measured at a given quality level, rather than the price per token or the score on a benchmark.
