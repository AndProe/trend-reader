Working memory

first seen 2026-W30 · 7 links · 3 min read

Working memory is what an agent knows about the current task right now: what it has done, what it has found, what remains. In the simplest designs it lives in the context window, which fills and degrades over long tasks. In current harness designs it is increasingly externalised: progress and intermediate results recorded by the machine rather than the model, collection maps and event logs built rather than remembered, file-based memory first with vector or graph stores later.

For an executive, working memory determines how long a task an agent can run reliably and how much it costs to keep it running. Failures show up as repeated work, contradictions and stale beliefs, and a benchmark of partially observable worlds names working memory and belief revision as the two failure modes. Products that promise persistent context across devices are building this layer as infrastructure, and long-term memory is openly described as unsolved even by teams shipping real-time generative systems.

Also seen as agent working memory, state tracking

Deeper dive

How it works. Within a session the model's context acts as working memory, but every token added competes with the task and the effect known as Context rot degrades recall as the window fills. Harness designers therefore externalise state. A compiled-skill approach records progress and intermediate results in a state machine rather than in the context; environment-evolution research builds collection maps and event logs as artefacts the agent consults; practitioners start with file-based memory and add vector or graph stores only when needed. Working memory is distinct from long-term memory, which persists across sessions, and from the KV cache, which is the model's own attention state and can itself go stale when documents are edited mid-task.

Why it matters now. Agents are running longer. The partially observable MNIST-PRO benchmark isolates two failure modes, working memory and belief revision, and shows that agents lose track of state they cannot see. Real-time generative systems face the same problem across infinite generation, where the question is what context to keep and discard, and their builders state that long-term memory is unsolved. Products now promise persistent cross-device context, which makes secure server-side memory the architecture requirement. Staleness has three named sources in one study, and edits to working memory are one of them. These pressures push memory from an emergent property of Long context to an engineered component.

Trade-offs. External memory is reliable and inspectable but must be designed per task, and the agent must be taught to consult it. In-context memory is flexible and needs no schema but is expensive and decays. Externalised state can itself become stale or inconsistent, and reconciling it with the model's beliefs is the belief-revision problem. Memory that persists raises privacy and retention questions that ephemeral context avoided, which is why the persistent variants ship with encryption and custody arguments.

What to watch. Agent benchmarks that score state tracking explicitly, harness conventions for externalised memory becoming standard, and whether Continual learning absorbs part of what working memory now carries.

Related terms

concept

Context rot

Context rot is the degradation of an AI agent's performance and memory reliability as its conversation history accumulates, even when the total stays within the model's nominal context window.

9 linksconcept

Long context

Long context refers to model context windows of hundreds of thousands to a million tokens, which allow an agent or a user to place entire codebases, document collections or multi-hour recordings in front of the model at once.

needed by 4 · 12 linkstechnique

Agent benchmarks

Agent benchmarks are evaluation suites that score an AI system on multi-step tasks inside an environment, such as repairing a code repository, operating a terminal or completing a task by voice, rather than on single-answer questions.

needed by 6 · 21 linkstechnique

Continual learning

Continual learning is the ability of a model to keep learning from its deployment, updating on new tasks, users and information while retaining what it already knows, instead of being frozen at the end of training.

9 linksconcept

Personalized agents

Personalized agents are AI agents that adapt their behaviour to one person's preferences, history and situation rather than responding identically for every user.

9 linksconcept

Generative video

Generative video is the class of models that synthesise video, and increasingly synchronised audio, from prompts rather than editing existing footage.
