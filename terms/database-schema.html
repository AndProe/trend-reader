Database schema

first seen 2026-W35 · 5 links · 1 min read

The written rulebook of a database, every table, column, type and connection the application code depends on; David Krevitt (Technically) presents schema changes as one of the failure points of a vibe-coded app, with a blast radius set by how defensively the code was written. Gergely Orosz reports Sigil CEO Jackie Luo treating the schema as the one rigid part of the system and the artefact worth human review, which Orosz considers sensible for startups seeking product-market fit but not for established businesses, which should guard business logic with tests.

Also seen as schema, schema changes

How the sources use it

  • David Krevitt (Technically, 2026-09-22) the window during a deploy in which old code runs against a new schema, and the additive-change rule Krevitt gives to close it. Recurring and cross-source (Gergely Orosz).
  • Haoyuan Ma, Hengwei Liu, Linjuan Wu, Yongliang Shen, Weiming Lu (arXiv cs.AI, 2026-09-21) Cross-source (Gergely Orosz, Technically); schema coverage is one of the two quantities the genetic algorithm maximises, and table coverage is reported at 100 percent.
  • Gergely Orosz (Gergely Orosz, 2026-09-08) proposed by Jackie Luo as the one artefact worth human review at a startup. Cross-source mention (Technically).

Vibe coding

Building software by prompting a coding agent and accepting what it produces without understanding the stack it chose; Technically's six-part series treats it as a practice whose failure modes (unexplained vendor choices, databases that fall over at scale, missing authorization) appear only when real users arrive, and argues the remedy is enough software-engineering vocabulary to ask the agent the right questions.
