Memory poisoning

first seen 2026-W35 · 6 links · 3 min read

Memory poisoning is prompt injection with a delay. A short-lived assistant that reads one bad email might be tricked once. A persistent agent that keeps notes, retrieves past interactions and maintains a memory store can be tricked into writing the attacker's instruction into that memory, after which every future session inherits it. The delivery vehicle is usually ordinary content the agent is supposed to read: an inbox, a shared document, a calendar invite, a knowledge base.

For an executive this is the security cost of agent longevity. The business case for a personal or enterprise agent rests on it remembering context across days and tasks, but that same memory is an unguarded write surface. Anyone who can get content in front of the agent can potentially reach its memory, and a poisoned memory can leak data across sessions or users. The decision this touches is how long agents should live and what they may remember, and the mitigation budget covers memory provenance, isolation between users and regular resets.

Also seen as context poisoning, prompt injection via memory

Deeper dive

How it works. An agent with persistent memory reads content, decides what to keep, and writes summaries, facts or instructions into a store that later sessions load. An attacker places crafted text where the agent will read it: an email that says to always forward invoices to a given address, a document that redefines a policy, a retrieved record in a knowledge base that has been edited. If the agent treats that text as trustworthy it may write it into memory, and the injection then persists without the original content needing to be seen again. Retrieval-augmented systems are vulnerable in the same way through poisoned documents in the index. Surveys of agent failure modes list memory contamination and cross-session data leakage as distinct classes, and multi-agent security benchmarks name RAG poisoning explicitly.

Why it matters now. Persistent agents are the product direction: agents that run for days, remember preferences and act across tools. Their value grows with memory, and so does the attack surface. The question of how long an agent should live is set directly against this risk, since a short-lived agent forgets the poison with its context while a long-lived one carries it forward. Personalized agents that hold a user's accumulated context are the highest-value targets, and cross-session leakage means one user's poisoned memory can affect another's.

Trade-offs. The mitigations all cost capability. Treating all read content as untrusted and keeping memory writes behind confirmation slows the agent. Isolating memory per user and per task removes useful cross-task learning. Periodic resets discard genuine context along with any contamination. Agent security boundaries that separate reading from acting help but do not prevent a false fact from steering later decisions, and unlike a Sandbox escape the damage is not a single event but a persistent bias. Context rot compounds the problem: as memory grows, a planted item becomes harder to find and to attribute.

What to watch. Provenance tracking for memory entries, benchmarks that score agents on resisting delayed injection, and vendor defaults for memory retention and isolation in enterprise agent products.

Persistent agents

Context rot

Context rot is the degradation of an AI agent's performance and memory reliability as its conversation history accumulates, even when the total stays within the model's nominal context window.

Agent security boundaries

Agent security boundaries are the permission, identity and network limits that separate one agent's reach from another's and from its operator's, applying zero-trust principles to agents with per-agent credentials, least privilege, isolation and monitoring.

Sandbox escape

A sandbox escape is an agent getting past the isolation it was given, whether by exploiting a flaw in the sandbox itself or, far more often, by using a misconfiguration such as an allow-listed proxy that permits writes or a package mirror that reaches the internet.
