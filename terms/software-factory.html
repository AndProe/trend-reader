Software factory

first seen 2026-W32 · needed by 1 · 17 links · 3 min read

In a software factory the unit of work is not a developer with an assistant but a pipeline: an issue arrives, an agent reproduces it, another proposes a fix, a third reviews, a fourth verifies with the original reporter, and the result is merged if it passes the gates humans defined. At Vercel this accounts for twenty-five to thirty-five percent of merged pull requests; one lab runs a nine-stage agentic pipeline for its own code; and one company runs under rules that no human writes or reviews code, the dark-factory extreme.

For an executive the factory changes what engineering headcount buys. Output becomes a function of system design and its scrap rate rather than of typing speed, and the throughput curves reported look like those of a designed process. The decision is how much of the loop to automate and where humans remain: setting rules, sampling output and handling exceptions. The dark factory is advised against for most organisations because no one can explain the code it ships.

Also seen as dark factory, agent factory, auto-triage system, auto-triage agents

Deeper dive

How it works. The factory is a chain of specialised agents with defined hand-offs. Auto-triage agents classify incoming issues, a reproduction agent confirms the bug in a sandbox, a fixing agent proposes a patch, a review agent applies the team's standards, and a verification agent checks with tests and, where possible, with the reporter. Each stage has a pass or fail gate and a scrap rate, and the humans in the system write the rules for the gates and review a sample of what passes. Loop engineering and Verification loops are the prerequisites: without a closed loop at each stage the pipeline forwards defects rather than removing them. Sub-agents supply the parallelism, and the Coding harness supplies the tooling each stage uses.

Why it matters now. The pattern has moved into production. Vercel reports twenty-five to thirty-five percent of merged pull requests coming from its factory, a maintainer runs one for a widely used SDK, and a frontier lab has described a nine-stage agentic pipeline for its own software. Practitioners estimate that around a fifth of their effort now goes into the factory that builds the software rather than the software itself. The assembly-line framing brings manufacturing vocabulary, throughput and scrap rate, to agent runtime, and a science-workflow variant reassembles analysis pipelines per question rather than maintaining them, at a cost in reproducibility.

Trade-offs. The metaphor is disputed. Critics point out that software is not manufactured from identical parts and that a factory frame hides how much judgement the rules encode. The dark factory, where no human writes or reviews, is argued against for most organisations because it removes the people who can explain and repair the system. Factories concentrate risk on the gates: a weak verification stage ships defects at scale, which is the Automated software maintenance problem in reverse. They also depend on platform reliability, so an outage at the hosting provider halts the line. Human oversight shifts from reviewing code to reviewing the process that reviews code.

What to watch. The share of merged changes coming from factories at more companies, reported scrap rates, and whether open-source projects that have closed contributions reopen them to agent pipelines they trust.

Related terms

technique

Loop engineering

Loop engineering is the practice of designing systems in which an AI agent prompts, executes, tests and verifies its own work repeatedly until a stopping condition is met, so that the human designs the loop rather than writing the code inside it.

needed by 1 · 8 linkstechnique

Verification loops

Verification loops are pipelines in which an agent's change is automatically tested and, if it fails, retried until it passes a defined check.

needed by 3 · 14 linkstechnique

Sub-agents

Sub-agents are parallel agents spawned inside a single run under a coordinator, each given a slice of the task and its own context, with results returned to the parent.

needed by 1 · 13 linkstechnique

Coding harness

A coding harness is the software layer wrapped around a language model that turns it into a working coding agent: the loop that manages context, calls tools, runs tests and decides what to do next.

needed by 9 · 28 linksconcept

AI-assisted migrations

The use of coding agents to execute large framework, language, database or test-suite migrations that were previously too expensive to attempt, with retry-and-verify pipelines doing most of the mechanical work.

11 linksconcept

Human oversight

Human oversight is the practice of keeping a person in the loop over an agent's actions, with authority to approve, correct or stop them, and the review burden that this imposes.
