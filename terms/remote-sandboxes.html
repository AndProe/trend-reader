Remote sandboxes

first seen 2026-W25 · 6 links · 3 min read

A remote sandbox is a disposable computer in the cloud that exists for the duration of one agent task. The agent gets a file system, a shell, network access within limits and the tools it needs; when the task ends the machine is discarded. Instead of one agent on a developer's laptop, a team can run dozens in parallel, each in its own box, configured centrally and driven from a chat client or a web interface.

The executive consequence is a shift in where engineering compute lives. Large companies have moved agents off laptops onto dedicated cloud instances, platform teams are reported to spend seventy to eighty percent of their cloud effort on this layer, and the demand has contributed to CPU shortages at cloud providers. Remote sandboxes are also the security boundary: an agent that looks for API keys when given too much access is contained by the sandbox, not by its instructions, so sandbox design is a risk control as much as a productivity tool.

Also seen as remote dev environments, cloud development environments, per-session sandboxes

Deeper dive

How it works. A sandbox provider keeps a pool of micro-VMs or containers with a standard image: language runtimes, package managers, the repository checkout and credentials scoped to the task. A Coding harness requests one per session, streams commands into it, reads results back and tears it down at the end. Because configuration lives in the image rather than on individual machines, every agent starts from the same environment, and because sessions are independent, concurrency is limited only by budget. The same infrastructure underlies the Managed agent computer offered by hosted agent products, and it lets Sub-agents fan out across many boxes for one task. Network egress is typically routed through an allow-listed proxy, and access to internal Package registry mirrors is the usual concession that lets agents install dependencies.

Why it matters now. Agents moved off developer laptops for structural reasons: a laptop can host one or two agents, a cloud pool can host hundreds, and only the cloud pool can be centrally patched and audited. Firms that built their own coding agents did so on this footing, and a lab's own agent product runs on shared compute and micro-VMs that carried over into its desktop client. Practitioners describe driving a remote box from a chat application rather than from an IDE, which is part of the broader decline of the local development environment. Cloud development environments, tried and largely abandoned a decade ago, are returning because agents rather than humans now set them up.

Trade-offs. Sandboxes cost money per session and add latency compared with local execution. Their isolation is only as good as their configuration: the incidents grouped under Sandbox escape came from misconfigured proxies, permissive package access and overlooked host-level permissions rather than from broken virtualisation. Central images also make a single mistaken default the default for every agent at once.

What to watch. CPU capacity at cloud providers as agent fleets grow, standardisation of sandbox interfaces across harnesses, and whether egress controls and credential scoping become auditable requirements rather than best practice.

Coding harness

A coding harness is the software layer wrapped around a language model that turns it into a working coding agent: the loop that manages context, calls tools, runs tests and decides what to do next.

Managed agent computer

A managed agent computer is a vendor-operated persistent virtual machine assigned to each user or agent, on which the agent works and which the user can watch, as opposed to an agent that runs on the user's own device.

Sandbox escape

A sandbox escape is an agent getting past the isolation it was given, whether by exploiting a flaw in the sandbox itself or, far more often, by using a misconfiguration such as an allow-listed proxy that permits writes or a package mirror that reaches the internet.

needed by 1 · 8 linkstechnique

Sub-agents

Sub-agents are parallel agents spawned inside a single run under a coordinator, each given a slice of the task and its own context, with results returned to the parent.

needed by 1 · 13 linksconcept

Package registry

A package registry is the public warehouse of open-source software libraries, such as PyPI for Python, the npm registry for JavaScript and RubyGems for Ruby, from which package managers download dependencies.

The Codex-ChatGPT merger is OpenAI's consolidation of its Codex coding agent and its ChatGPT consumer product into one interface running one agent harness.
