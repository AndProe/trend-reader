Prefill-decode disaggregation

first seen 2026-W35 · 6 links · 3 min read

Serving a language model has two phases. Prefill reads the whole prompt at once and is compute-heavy; decode produces one token at a time and is limited by memory bandwidth. Running both on the same accelerator wastes capacity, because each phase leaves the other's bottleneck idle. Disaggregation puts prefill on one set of machines and decode on another, handing over the intermediate state, the KV cache, across a fast network. Inference vendors and the leading GPU stack use it as the default for large deployments.

For an executive the relevance is cost and vendor choice. Disaggregation is a large part of why some hardware delivers far better performance per dollar on agentic workloads, and its absence from an inference stack, as with parts of the externalised TPU offering, shows up as a gap in benchmark results. OpenAI's Jalapeño chip deliberately leaves it out, betting on a different balance. Buying inference capacity therefore means asking not only which chip but which serving architecture sits on top of it.

Also seen as PD disaggregation, disaggregated serving

Deeper dive

How it works. Prefill runs the prompt through the model in one parallel pass, producing the KV cache that stores attention state for every token. Decode then generates tokens sequentially, reading that cache at each step. Prefill saturates compute; decode saturates memory bandwidth and benefits from large batches of concurrent requests. Disaggregated serving assigns each phase to a pool tuned for it, for example an 8-plus-8 split of accelerators, and transfers the cache over high-speed interconnect. Research extends the idea further, splitting decode itself by attention type across heterogeneous hardware. Experiments with memory offloading find that keeping richer intermediate state on the prefill side hands decode workers a better cache and yields more correct answers.

Why it matters now. Agentic inference workloads have long prompts, tool outputs and repeated context, which makes prefill a much larger share of total work than in chat. Disaggregation is the serving technique behind the strongest GPU results in independent agentic inference benchmarks, and it depends on mature software, which is part of the CUDA moat argument. The choice also shapes the trade between Interactivity versus throughput, since decode pools can be tuned for latency while prefill pools are tuned for bulk work. Custom silicon makes the opposite bet visible: the Jalapeno chip is designed without disaggregation, aiming to make a single integrated design efficient enough that the handover is unnecessary.

Trade-offs. Moving the cache between pools costs bandwidth and adds latency to the first token, and the split only pays off at scale, since small deployments cannot fill two specialised pools. Capacity planning becomes harder because the ratio of prefill to decode hardware must track a workload mix that changes by the hour. Software complexity rises, which is why stacks lacking a mature disaggregation layer trail on benchmarks even with competitive chips. Aggregated serving remains the simpler choice for short prompts and modest concurrency.

What to watch. Whether externalised TPU and other non-Nvidia stacks close the software gap, how integrated custom chips perform on long-context agentic traffic, and whether cache transfer becomes standardised enough to run across mixed hardware.

KV cache

The KV cache is the per-token store of key and value vectors that a transformer keeps during generation so it does not recompute attention over the whole context on every step.

Agentic inference workloads are the production traffic pattern created by coding and computer-use agents: many turns per task, context that accumulates toward a million tokens, very high reuse of shared prefixes, and bursts of parallel sub-agent calls.

Interactivity versus throughput

Interactivity versus throughput is the trade-off every inference system sits on: raising the tokens per second a single user receives lowers the total tokens a GPU can serve, by roughly thirty times throughput for a tenfold gain in speed.

CUDA moat

The CUDA moat is Nvidia's software advantage: a mature programming stack and same-day framework support that make its GPUs the default target for every serving engine.
