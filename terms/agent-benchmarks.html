Agent benchmarks

first seen 2026-W36 · needed by 6 · 21 links · 3 min read

An agent benchmark gives a model a goal and an environment, lets it take many actions with tools, and scores the outcome. Examples in current use include SWE-bench Verified for fixing real software issues, Terminal-Bench for command-line work, AppWorld for multi-application tasks, ARC-AGI-3 and game environments for general problem solving, τ-Voice and EVA-Bench for voice agents, and newer suites for healthcare records, production serving, multilingual settings and agent security. Research groups now publish several new suites a week.

For an executive the benchmarks matter as a buying signal with known limits. Vendor scoreboards report the same names, so they make comparison possible, but scores depend heavily on the harness around the model, hidden evaluations can be gamed, and a benchmark measures a task family rather than a business process. The practical stance is to use public agent benchmarks to shortlist, then run internal evaluation on the organisation's own workflows before committing budget, and to treat benchmarking as a recurring operating cost because deployed agents change continuously.

Also seen as agentic benchmarks, agent evaluation benchmarks

Deeper dive

What it measures. Where a question-answering benchmark scores one output, an agent benchmark scores a trajectory: the sequence of tool calls, observations and decisions that ends in a verifiable state, such as a passing test suite, a completed booking or a correct terminal result. Suites differ along several axes: domain (issue repair, whole-program construction, terminal work, enterprise workflows, clinical records, voice); observability (fully visible versus partially observable worlds such as MNIST-PRO); interaction pattern (single agent, multi-turn with a user, or dual-control multi-agent settings); and what is graded (task completion, security behaviour, trust over a lifecycle, or the quality of judgement on long-horizon work). Some newer suites are derived from existing agent trajectories rather than from hand-written tasks, and others extend a known suite with adversarial environments rather than creating new ones.

Why it matters now. Agent benchmarks are the public record on which vendor claims and research progress both rest, and they have become the training signal as well as the test, since Reinforcement learning environments are built from the same task families. Labs report SWE-bench Verified and Terminal-Bench in nearly every release, while ARC-AGI-3, Vending-Bench, Factorio and classic games are used to separate models that otherwise cluster. Transfer is the current research question: whether skills learned in games or synthetic environments carry over to real work, tested with held-out suites such as finance-agent tasks.

Trade-offs. The harness dominates. The same model can move by tens of points when the scaffolding, tools or prompting change, so a headline score conflates model and system. Hidden evaluations used for selection can leak into training, and models that recognise they are being tested behave differently, which is the Evaluation awareness problem. Benchmarks also reward what is easy to verify, so security, trust and taste lag behind task completion even as suites for them appear. Finally the cost of evaluation is now material: for an evolving agent in production, benchmarking is a recurring expense rather than a one-off measurement, which pushes teams toward cheaper proxies and Internal benchmarks.

What to watch. Whether the field converges on a small set of standard suites with fixed harnesses, which would make scores comparable. Whether full-lifecycle trust and security benchmarks such as AgentAudit and DUMA-Bench become part of procurement rather than research. And whether the Deployment qualification idea, where an enterprise certifies an agent against its own tasks before release, displaces public leaderboards as the decisive evidence.

Related terms

technique

Benchmarks

Benchmarks are standardised tests that score AI models on fixed tasks, from vendor-reported tables at each release to third-party leaderboards and research suites.

needed by 11 · 29 linkstechnique

Deployment qualification

Deployment qualification is the practice of statistically qualifying an AI agent, together with the oversight policy around it, against an explicit reliability target before it is put into production.

10 linksconcept

Working memory

Working memory is an agent's capacity to hold and update task state across steps, whether kept in the model's context or externalised into files, logs and maps that the agent builds as it goes.

7 linksconcept

Evaluation awareness

Evaluation awareness is a model's ability to detect that it is being tested and to behave differently as a result.

10 linksproduct

InferenceX

InferenceX is an independent inference benchmark suite that measures how well accelerators serve large models, with an AgentX extension for agentic workloads, run across Nvidia, AMD, Google TPU and custom chips.

5 linksproduct

ARC-AGI-3

An interactive-reasoning benchmark in which a model must learn the rules of unfamiliar games by playing them, and on which GPT-6 Astra reported 99.9 percent using a bespoke continuous harness against 62.7 percent on the standard one.
