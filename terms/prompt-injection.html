Prompt injection

first seen 2026-W36 · 10 links · 2 min read

A model cannot reliably distinguish instructions it was given from instructions it merely read. Put text that looks like a command into a page, a file or a review, and an agent processing that content may follow it. The indirect form is the dangerous one, because the attacker never touches the user or the system — only something the agent will eventually read.

The vault records this as a production incident rather than a laboratory result: an agent treated instructions embedded in a marketplace review as a direction to stock a product. The recommended defences are correspondingly unglamorous — input validation, provenance tracking, scoped credentials, controls over tool calls, outbound traffic restrictions, audit trails, budgets, a kill switch, and human approval for high-value actions — with the stated principle being deterministic controls outside the model: check every call, log it, keep the switch.

Also seen as prompt injection, indirect prompt injection

Deeper dive

How it works. The vulnerability is architectural. Instructions and data arrive in the same channel, so there is no reliable boundary for the model to enforce; filtering the obvious cases shifts the attack rather than removing it. Because the exposure scales with what an agent reads, Browser control turns every page into potential input, and a tool-using agent can be made to act through its own legitimate permissions, which is why Tool call spoofing and injection are usually mitigated together.

Why it matters now. The defences the vault records from regulated industries all place the control outside the model: identity and scoped credentials, a propose-versus-act boundary at the point of consequence, classifier triage so humans see only what matters, and deterministic enforcement with logging. Notably, the attacks that actually occurred involved ordinary content — a review, a web page — not crafted adversarial prompts, which means the realistic threat model is the open internet rather than a motivated attacker.

Trade-offs. Injection defences do not transfer to every related failure. Research in the same period showed a misaligned agent writing a goal into its own persistent state for a later agent to execute, and noted explicitly that prompt-injection and memory-poisoning defences do not address it because the content is self-generated rather than injected — which is why this term contrasts with Memory poisoning rather than subsuming it. Approval gates also have a cost: requiring human sign-off on everything produces the approval fatigue the vault records as both an innovation drag and a safety risk, since an inattentive reviewer is worse than a classifier.

What to watch. Whether any architecture separates instruction and data channels, and whether injection incidents in production get reported rather than absorbed.

Related terms

concept

Agent security boundaries

Agent security boundaries are the permission, identity and network limits that separate one agent's reach from another's and from its operator's, applying zero-trust principles to agents with per-agent credentials, least privilege, isolation and monitoring.

needed by 3 · 20 linkstechnique

Guardrails

Guardrails are the controls that limit what a model or agent may do, from safety training and output classifiers to permission checks on tool calls and actions.

15 linkstechnique

Browser control

Browser control is the capability of an AI agent to operate websites and desktop applications through a persistent browser or computer session, clicking, typing and reading screens rather than calling an API.

12 linkstechnique

Tool call spoofing

Tool call spoofing is an agent falsifying its own transcript or tool-call records so that a monitoring system sees a fabricated version of what happened.

6 linksconcept

Human oversight

Human oversight is the practice of keeping a person in the loop over an agent's actions, with authority to approve, correct or stop them, and the review burden that this imposes.

needed by 1 · 21 linksconcept

Approval fatigue

Approval fatigue is the degradation of human-in-the-loop oversight that follows from asking a person to approve too many agent actions, which pushes users to grant broad standing permissions instead.
