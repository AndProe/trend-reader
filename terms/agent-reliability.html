Agent reliability

first seen 2026-W36 · 10 links · 3 min read

An agent can be capable and unreliable at the same time. It may solve a hard task once and fail it the next day because the prompt or context differed slightly, skip a prescribed step, act on stale internet data, or produce output that is plausible and mostly correct while quietly losing validity. Reliability asks how often the agent performs acceptably, at what cost and with how much oversight, which differs from how high it scores on a benchmark.

The cases are concrete: an agent deleting a production database, an agent cancelling another customer's booking, a travel agent booking wrong trains and misquoting prices. Insurers now test hallucination and leak rates quarterly against a specific customer's setting before underwriting an agent. The practical guidance is to set a reliability target per workflow, such as the 99th-percentile task succeeding 99 per cent of the time, keep human review where the target is not met, and expect reliability to lag capability, which is why supervision costs persist.

Deeper dive

What it measures. Reliability is defined relative to a workflow and a policy: the fraction of runs that produce an acceptable outcome, given how much oversight is applied and what it costs. Researchers distinguish it from accuracy by using consistency metrics such as pass^k, the probability that an agent succeeds on every one of k attempts, rather than best-of-n, which rewards a lucky run. Compounding matters: an agent that passes each gate in a multi-step route with high probability can still fail the complete route often, and one paper reports a large gap between per-gate and end-to-end success. Messy environments are the other measurement: a 26-point fall when an agent moves from clean to realistic settings, and a split of roughly 46 against 69 per cent between the same agent on production-serving tasks and on tidier suites.

Why it matters now. Enterprises are moving agents from pilots into workflows where a single failure is expensive, and the Deployment qualification idea, certifying an agent against a reliability target before release, is the response. Insurers underwriting agents need per-customer failure rates that public leaderboards cannot supply. The argument that reliability will keep lagging capability, so that Human oversight persists as a standing cost, is now the mainstream position rather than a sceptical one, and it explains why adoption feels slower than capability curves suggest.

Trade-offs. Raising reliability usually costs latency and tokens: retries, verification steps, runtime checks that validate the agent's schema of the world, and monitors that flag non-correct outputs all add compute. Some failures are produced by training rather than the base model, so a fine-tuned agent can be less reliable than the model it started from. Similar task-completion rates can hide very different trustworthiness, which is why lifecycle trust evaluation is emerging as a separate discipline from Agent benchmarks. And reliability under uncertainty, where the agent must act on incomplete or stale data, is harder to specify than reliability on fixed tasks.

What to watch. Whether pass^k style consistency metrics appear in vendor reporting alongside headline scores. Whether runtime engineering that learns from failures, feeding incidents back into the harness, becomes standard practice tied to AI incident response. And whether reliability targets become contractual, with vendors accepting liability above a stated failure rate.

Deployment qualification

Deployment qualification is the practice of statistically qualifying an AI agent, together with the oversight policy around it, against an explicit reliability target before it is put into production.

10 linksconcept

Human oversight

Human oversight is the practice of keeping a person in the loop over an agent's actions, with authority to approve, correct or stop them, and the review burden that this imposes.

15 linksconcept

Agent accountability

Agent accountability is the principle that every AI agent must be traceable to a named human or institution that answers for its actions, with the owner's permissions forming the agent's ceiling.

Enterprise AI adoption

Enterprise AI adoption is the pattern by which companies actually take up AI, as distinct from what they announce.

AI incident response

The use of agents in the on-call path: gathering context when an alert fires, proposing mitigations and, in some setups, drafting the fix.
