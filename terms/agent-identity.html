Agent identity

first seen 2026-W34 · needed by 1 · 11 links · 3 min read

Giving an agent an identity means treating it the way an organisation treats a new employee or service: it gets its own account, credentials, a name, a record of what it has done, and permissions attached to that record. The identity survives restarts and, in current lab practice, model upgrades, so the audit trail stays continuous when the underlying model changes. Operating-system vendors now register agents as first-class users with human-equivalent observability, and household assistants get their own accounts.

For an executive, identity is the first governance layer and the prerequisite for everything else: accountability, least-privilege permissions, revocation and incident forensics all depend on it. It is also a product lever, since consumer agents with a stable named character are used habitually in a way anonymous chat threads are not. The decision is whether to build identity into the agent platform from the start or retrofit it once agents are embedded in workflows, which is harder and leaves unregistered agents for security tooling to hunt.

Also seen as persistent bot identity, agent identity layer

Deeper dive

How it works. An agent identity binds three things: a durable identifier that persists across sessions, credentials that let the agent authenticate to systems in its own name rather than through a shared login, and a record of actions attributed to that identifier. Enterprise directory services now issue identities to agents so that an agent appears as a user in the operating system, can be monitored like one and can be revoked like one, with security scanners detecting agents that fail to register. At the lab level, one frontier lab ties every action and record to a per-agent identity that survives model upgrades, so an agent's history is continuous across the models that have powered it. Protocol proposals for agent interaction include identity in their security-by-design sections, and a benchmark now exists that tests whether deployed agents maintain a consistent identity rather than merely recalling facts.

Why it matters now. Agents are becoming persistent. Persistent agents that run for weeks, hold memory and act across systems cannot be governed as anonymous threads. On the product side, a consumer bot design that gave each agent a stable named character rather than disposable threads was credited with driving daily habitual use. On the governance side, identity is the base layer for Agent accountability and for Agent security boundaries: per-agent credentials replace shared logins, and an owner can only be assigned to something that has a name. Interoperability across vendors, the goal of Agent protocols, also assumes agents can identify themselves to each other.

Trade-offs and open questions. Persisting identity across model upgrades is administratively convenient but philosophically awkward: an objection raised against it is that swapping the model under a fixed identity breaks the agent's own self-model, so the name continues while the thing behind it changes. Identity also interacts with rights debates; the argument in the evidence is that agents need identity before any question of rights can be posed, and that identity is not the same as AI consciousness. Practically, strong identity raises the cost of spinning up agents freely, and organisations that rely on ephemeral sub-agents will need an identity model that covers short-lived children as well as long-lived parents.

What to watch. Whether directory and identity vendors make agent identities standard, which would make the practice default rather than bespoke. Whether persistent-identity benchmarks are adopted in procurement. And whether cross-vendor identity assertions appear in agent protocols, so that an agent from one platform can be recognised and permissioned on another.

Agent protocols

Agent protocols are the emerging standards that define how agents call tools, talk to each other and operate devices across vendors, with MCP, A2A, NLIP and a model hardware standard as the current proposals.
