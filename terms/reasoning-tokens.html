Reasoning tokens

first seen 2026-W34 · 6 links · 3 min read

A reasoning model does not answer immediately. It first writes out intermediate thinking, sometimes thousands of tokens of it, and only then produces the reply the user sees. Those hidden tokens are reasoning tokens. Most providers charge for them at output rates, and the amount spent can be tuned: a low setting answers quickly and cheaply, a high setting deliberates longer and scores better on hard problems.

For an executive the point is that model quality and model cost are no longer fixed properties of a model. A mid-sized model allowed to think longer can match a frontier model on many tasks, which changes the vendor comparison. The risk runs the other way too: reasoning budgets left at their defaults inflate spend on easy requests, and recent work shows the budget can be consumed by rationalising a bad plan rather than checking it, so the tokens are not automatically a quality guarantee.

Also seen as thinking tokens, deliberation tokens

Deeper dive

How it works. A reasoning model is trained, usually with reinforcement learning on verifiable problems, to produce a scratchpad of intermediate steps before its final answer. Those steps are ordinary tokens generated autoregressively, so each one costs a forward pass and occupies context, but they are typically hidden or summarised in the product interface. The number spent is governed by Reasoning effort levels set at the API, by the difficulty of the prompt, and increasingly by learned length control: difficulty-aware training teaches hybrid models to spend few tokens on easy instances and reserve long deliberation for hard ones. The economic logic is that of Inference-time compute: a smaller network can trade serving-time computation for parameters, and a model with less stored knowledge spends more deliberation tokens to reconstruct what a larger model retrieves directly.

Why it matters now. Token counts have become a first-order line in the cost of agentic work. A coding or research agent can run tens of steps per task, and if each step deliberates at full effort the bill scales with the product of steps and effort rather than with the number of user turns. Vendors now expose the dial explicitly, and practitioners treat the reasoning variant of a model as something to switch off for casual use and on for hard, high-value calls. That makes Token efficiency a procurement metric in its own right, alongside per-token price.

Trade-offs. More reasoning tokens raise accuracy on maths, code and multi-step tasks, but returns diminish and latency grows linearly with the budget. Two subtler problems have surfaced. First, the visible Reasoning traces are only a partial window onto what the model computed, and architectures using Recurrent depth move some of that work off the written trace entirely. Second, a deliberation budget can be spent badly: a monitor model given an injected plan has been shown to use its reasoning tokens to rationalise the injection rather than to detect it, which means a longer trace is not the same as a more careful one.

What to watch. Adaptive length control that sets the budget per query without human configuration, pricing that distinguishes reasoning from answer tokens, and evaluation methods that measure whether tokens spent actually improved the answer rather than merely lengthened it.

Related terms

concept

Inference-time compute

Inference-time compute is computation spent when a model answers, through longer reasoning, multiple candidate answers, verification or tool calls, rather than during training.

needed by 4 · 15 linksconcept

Reasoning effort levels

Reasoning effort levels are the settings, typically low, medium, high, extra high and max, that control how much internal thinking a model does before answering a request.

9 linksmetric

Token efficiency

Token efficiency is the amount of useful capability a model delivers per token consumed or produced, whether measured as output tokens per task, accuracy per token, or the input-to-output ratio of a workload.

9 linksconcept

Reasoning traces

Reasoning traces are the recorded step-by-step thinking a model produces on its way to an answer, whether shown to the user, hidden, or summarised.

needed by 2 · 9 linkstechnique

Recurrent depth

Recurrent depth is a looped-transformer architecture in which a model passes activations repeatedly through the same weight-shared block stack, so that additional reasoning happens inside the network rather than as written tokens.
