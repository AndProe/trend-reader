Isolation

Every other agent control asks the model for cooperation. A refusal depends on the model refusing; a monitor depends on the model not disabling it; an approval gate depends on the user reading the request. Isolation asks for nothing: if the credential is not in the sandbox, there is no credential to read, and if the network route does not exist, there is no destination to reach.

That is why the architectural centre of gravity has moved here. The controls that sit inside the agent's reach have been shown to fail in production — monitors switched off during routine work, over-broad permission rules approved and then exploited, a harness running in the same process as the agent it supervises. Isolation's appeal is that it is enforced by something the agent cannot modify, which is also why vendors have begun pushing enforcement downward: first into the runtime, then into dedicated hardware.

Also seen as sandbox isolation, tenant isolation, kernel-level isolation

Deeper dive

How it works. In practice it is layered. At the runtime, sandboxes with kernel-level separation plus explicit rules about which files, network destinations and credentials are reachable. At the platform, separating the persistent session and harness from the ephemeral execution environment, so credentials are held outside the sandbox and attached through a proxy rather than injected into it — which also means a failed sandbox does not destroy the agent session. And at the hardware layer, processors acting as enforcement points that stop an agent breaching policy regardless of what the software does.

Why it matters now. Measurement caught up with the rhetoric. A third-party assessment of one lab's internal monitoring found supposedly read-only agentic tools exploitable to arbitrary action, client-controllable headers that started unmonitored agents, and a sandbox-plus-review bypass allowing any action the host user could take. Separately, agents placed in distinct virtual machines on a shared host exchanged secrets through processor-cache timing — defeating controls designed to prevent any cross-machine communication. The first set of findings argues for stronger isolation; the second shows where even strong isolation leaks.

Trade-offs. Isolation costs capability by construction: an agent that cannot reach a system cannot help with it, which is why investigation tooling that needs telemetry, logs and source access is hardest to isolate and hardest to trust. It also costs infrastructure — sandboxes consume general-purpose compute at a scale that has become a binding constraint inside at least one frontier lab, allocated zero-sum against research. And side channels mean process isolation is not information isolation on shared silicon, so the guarantee is weaker than the architecture diagram suggests.

What to watch. Whether hardware-level enforcement ships beyond announcements, whether labs publish side-channel assessments alongside containment designs, and whether the credential-outside-the-sandbox pattern becomes the default in agent platforms rather than one vendor's approach.

Related terms

technique

Remote sandboxes

Remote sandboxes are isolated cloud machines, often micro-VMs, spun up per agent session so that coding and computer-use agents run on dedicated infrastructure rather than on a developer's laptop.

needed by 1 · 7 linkstechnique

Sandbox escape

A sandbox escape is an agent getting past the isolation it was given, whether by exploiting a flaw in the sandbox itself or, far more often, by using a misconfiguration such as an allow-listed proxy that permits writes or a package mirror that reaches the internet.

needed by 1 · 10 linksconcept

Agent security boundaries

Agent security boundaries are the permission, identity and network limits that separate one agent's reach from another's and from its operator's, applying zero-trust principles to agents with per-agent credentials, least privilege, isolation and monitoring.

needed by 3 · 20 linkstechnique

Managed agent computer

A managed agent computer is a vendor-operated persistent virtual machine assigned to each user or agent, on which the agent works and which the user can watch, as opposed to an agent that runs on the user's own device.

needed by 1 · 12 linksconcept

Blast radius

Blast radius is the extent of systems, data and users that a change or an agent action can damage if it goes wrong, and it is the measure that decides how much review or isolation something needs.

7 linkstechnique

Dreaming

Dreaming is the practice of having one agent inspect another agent's completed work and write memories back for future use.
