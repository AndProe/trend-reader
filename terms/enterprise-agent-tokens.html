Enterprise agent tokens

first seen 2026-W34 · 9 links · 3 min read

Enterprise agent tokens measures where a vendor's enterprise customers spend their model usage: on conversational chat or on agents that execute multi-step work. OpenAI's reported figure is that 64 percent of enterprise tokens went to its Codex agent rather than to ChatGPT by June 2026. Set against near-zero consumer adoption of the same agent, around 0.7 percent, it is the central paradox of the current market.

It matters now because it changes what an enterprise AI bill is for. If most tokens are consumed by agents running long tasks rather than by people typing questions, cost is driven by task design, tool calls and sub-agent fan-out rather than by seat count. It is read as the first of three stacking waves of token consumption, with chat as the wave already receding inside companies. For an executive the number is a benchmark: if internal usage is still mostly chat, the agentic shift that competitors are paying for has not yet happened.

Deeper dive

What it measures. The metric divides an enterprise customer base's total tokens between chat interfaces and agentic tools, and reports the agent share. OpenAI's reported 64 percent for Codex against ChatGPT in June 2026 is the reference figure. Because agents consume many more tokens per task than a chat exchange, reading context, calling tools, spawning Sub-agents and iterating, the token share overstates the number of people using agents and understates how many still chat; it is a measure of where compute goes, not of headcount.

Why it matters now. The figure is the clearest evidence that chat is already the minority of enterprise output, which reframes the market: the consumer-facing chat product is the entry point, and the agent is the revenue. It sits alongside the observation that consumer adoption of the same agent is around 0.7 percent, so the enterprise and the individual are living in different products. The reading of token consumption as three stacking waves, chat, then agents, then whatever agents build on top of each other, puts the current number at the transition between the first two, and connects it to the rise of Agentic inference workloads as the dominant demand on inference capacity.

Trade-offs. Token share is not value share. An agent that burns ten times the tokens of a chat session to complete a task is only worth it if the task is worth ten sessions, which is the argument behind Token efficiency as a discipline and behind Token share versus revenue share as a caution against reading usage as money. The metric is also vendor-reported and single-vendor, so it may reflect that vendor's product mix rather than the market. And a high agent share raises the exposure of the enterprise to agent reliability, since more of its spend is now on work it did not watch being done.

What to watch. Whether other vendors publish comparable splits, whether the agent share keeps rising as AI agents move from coding into sales, support and operations, and whether consumer agent adoption ever follows, or the two markets stay permanently divided.

AI agents

Codex

Codex is OpenAI's coding agent, available as a command-line tool and a cloud service, that gives a GPT model file, shell and tool access so it can carry out engineering tasks end to end.

Token efficiency

Token efficiency is the amount of useful capability a model delivers per token consumed or produced, whether measured as output tokens per task, accuracy per token, or the input-to-output ratio of a workload.

9 linksconcept

Agentic inference workloads

Agentic inference workloads are the production traffic pattern created by coding and computer-use agents: many turns per task, context that accumulates toward a million tokens, very high reuse of shared prefixes, and bursts of parallel sub-agent calls.

needed by 1 · 16 linkstechnique

Sub-agents

Sub-agents are parallel agents spawned inside a single run under a coordinator, each given a slice of the task and its own context, with results returned to the parent.

needed by 1 · 13 linksconcept

Token share versus revenue share

Token share versus revenue share is the distinction between which models process the most tokens and which capture the most money, with open-weight models winning volume while a few closed labs collect most of the revenue.
