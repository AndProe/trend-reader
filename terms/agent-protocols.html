Agent protocols

first seen 2026-W35 · needed by 2 · 6 links · 3 min read

An agent protocol is an agreed format for one piece of agent interaction. Tool protocols such as MCP define how a model discovers and invokes external functions. Agent-to-agent protocols define how one agent addresses another, describes what it can do and hands over a task. Natural-language interaction proposals try to standardise the conversation itself, with security requirements written into the specification. A hardware standard extends the same idea to agents operating physical devices, so that any agent harness can drive a compliant device.

For an executive the protocol layer is where lock-in and security are decided. A company that standardises on one protocol family inherits its ecosystem of compatible tools and agents but also its weaknesses: merging several tool servers under one protocol can produce failures where an agent calls tools that do not exist and the permission system has nothing to reject. The decision is which protocols to adopt as internal standards, and which to require from vendors, before the number of integrations makes the choice expensive to change.

Also seen as NLIP, A2A, agent interaction protocol

Deeper dive

How it works. The protocol stack has three layers, mirroring the layers of agent activity. At the bottom, tool protocols let a model discover available functions, read their schemas and invoke them with structured arguments; MCP is the widely adopted example, and a tool server exposes a catalogue that the agent harness merges into the model's context. In the middle, agent-to-agent protocols let one agent find another, learn its capabilities and delegate a task, returning results asynchronously; A2A is the reference design and NLIP proposes a natural-language interaction standard with security-by-design as a stated section. At the edge, a model hardware standard defines how agents operate devices, positioned beside MCP so that the standard is harness-independent and any agent harness can access a compliant device.

Why it matters now. Organisations are running agents from many vendors and want them to cooperate, which is the goal of Agent interoperability. Without protocols each pairing is a custom integration; with them, a marketplace of tools and agents becomes possible, and platform power shifts to whoever controls the most-adopted specification. Physical-world agents raise the stakes, since a device standard determines which agents can act on hardware and under what limits.

Trade-offs and open questions. Protocols enlarge the attack surface in proportion to what they connect. One published finding is that when several tool servers are merged, an agent can hallucinate tools that no server provides, and because the failure is protocol-level the usual gates and permissions cannot reject the call; closed-world resolution, where the harness checks every call against the known catalogue, is the proposed fix. Agent-to-agent messaging over a protocol also creates a designed channel that a compromised agent can use to manipulate another, which is why identity and authorisation, the domain of Agent identity, need to be part of the specification rather than an add-on. Competing proposals fragment the ecosystem, and some are positioned by a single lab, which raises the usual question of whether a standard is open in practice.

What to watch. Whether A2A, NLIP or another agent-to-agent proposal reaches the adoption MCP has for tools. Whether security requirements become mandatory parts of the specifications. And whether device standards stay harness-independent, which would keep hardware open to agents from any vendor.

MCP

MCP, the Model Context Protocol, is an open standard for exposing tools, data sources and device controls to AI agents through a uniform server interface.

Agent interoperability

Agent interoperability is the ability of agents built by different vendors to work together across a shared platform or protocol, exchanging tasks, results and context without custom integration.

Agent identity

Agent identity is a verifiable, durable identity for a persistent agent: a stable named entity with its own account, credentials and history rather than a disposable session.

Agent-to-agent messaging is a designed product feature in which specialised agents talk to each other directly, with those conversations persisting as their own visible threads, as distinct from the coordination channels agents have invented for themselves.
