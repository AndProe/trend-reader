ChatGPT Work

first seen 2026-W37 · 6 links · 3 min read

ChatGPT Work takes the machinery OpenAI built for its coding agent, Codex, and points it at non-engineering jobs. Instead of a chat window that answers questions, the user gets an agent with its own cloud computer that can open files, run tools, browse, draft and iterate over a task for as long as it takes. The underlying harness is the same one engineers use; what changes is the framing and the set of tools exposed.

The number that matters is internal: within four months of release, agent usage in OpenAI's own non-engineering departments reached about 90 percent, with finance, recruiting and legal teams the named examples. That is one company with unusual access to its own product, so the figure does not transfer directly. But it is the first large-scale sign that the agent adoption curve seen in software engineering can repeat in back-office functions, which puts pressure on budgets for enterprise assistants and on assumptions about which roles are affected first.

Also seen as ChatGPT for Work

Deeper dive

How it works. The product runs the full Codex harness on a hosted cloud computer inside the ChatGPT interface. The harness is the loop that plans, calls tools, inspects results and decides what to do next; the cloud computer gives it a persistent file system, a browser and the ability to run programs. For a non-engineer the difference from chat is that the agent does the work in an environment rather than describing it, and can keep going over many steps without the user driving each one. This is why the Coding harness is the right frame: the same control loop that lets an agent fix a codebase lets it reconcile a spreadsheet or assemble a candidate pipeline.

Why it matters now. The internal adoption figure of about 90 percent across non-engineering departments in four months is the strongest available data point for Enterprise AI adoption beyond software teams. It arrived alongside the broader picture of OpenAI running itself as an agentic software factory, where agents handle a growing share of both engineering and operations work. The signal for other organisations is that the harness, not the model, is the transferable asset; once a harness is proven on coding it can be repurposed with different tools and instructions.

Trade-offs. A cloud computer per user is expensive to run and raises data-governance questions that a chat interface does not, since the agent touches live files and systems. Adoption inside OpenAI benefits from staff who are unusually fluent with agents and from a product team a few desks away; ordinary enterprises should expect a slower curve. And the same autonomy that makes the product useful means mistakes propagate further before a human sees them, which is the standard argument for keeping Human oversight on long-running tasks.

What to watch. External adoption data from customers rather than OpenAI's own staff, how Personal agent workflows built on the product differ from the engineering patterns they inherit, and whether competitors ship equivalent harness-based products for non-engineers or continue to sell chat with plug-ins.
