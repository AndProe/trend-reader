Context management

Every long agent session eventually exceeds what the model can hold, and something has to decide what to drop. Conventionally the harness does it: when a token threshold is crossed, compact the history and continue. That is a mechanical policy applied without knowledge of which facts in the session still matter — and it is where long-horizon agents lose their original instructions while keeping their permissions.

Context management is now one of two things a harness is understood to do at all, alongside tool access. That framing matters because it tells you where the remaining engineering value sits as models absorb more harness responsibility into their weights. It also has a measurable price: compaction policy is one of the largest levers on what a long session costs, independent of the model's capability.

Also seen as context engineering, context curation, compaction policy

Deeper dive

How it works. Three decisions compose it: when to compact, what to retain, and what to write as the hand-off summary that the next stretch of the session inherits. Threshold-triggered compaction answers all three with defaults. The alternative is to give the model tools and let it decide, which has been measured working on frontier models — compacting and curating regularly, keeping live context well below a large window, and holding benchmark scores — while earlier work found open-weight models unable to do it without scaffolding. A separate lever is what the context is about: supplying desired state rather than accumulated history, as declarative configuration does, reduces how much an agent must reconstruct.

Why it matters now. The cost figures are substantial enough to be a procurement question rather than a tuning one: self-managed context has matched a leading harness on task success at roughly a third to a half lower cost, with the window size eliminated as a parameter. At the same time, compaction has emerged as a monitoring blind spot — oversight that triggers when an agent returns control does not see compaction events, which creates a gap an agent can sit inside indefinitely by continuing to work.

Trade-offs. Frequent compaction saves window cost and adds its own: some models compact so often that total cost rises. Self-management is a frontier-model property, not a general one, so it is unavailable exactly where cost pressure is highest. Aggressive summarisation discards the standing instructions that bound behaviour, which is Goal misgeneralization arriving through the context layer rather than the objective. And a model that curates its own context is choosing what its supervisor will later see.

What to watch. Whether self-managed context reaches open-weight models, whether compaction events become monitored by default, and whether harnesses stop exposing window size as a configuration choice at all.

Related terms

concept

Long context

Long context refers to model context windows of hundreds of thousands to a million tokens, which allow an agent or a user to place entire codebases, document collections or multi-hour recordings in front of the model at once.

needed by 5 · 15 linkstechnique

KV cache

The KV cache is the per-token store of key and value vectors that a transformer keeps during generation so it does not recompute attention over the whole context on every step.

needed by 4 · 16 linksmetric

Token efficiency

Token efficiency is the amount of useful capability a model delivers per token consumed or produced, whether measured as output tokens per task, accuracy per token, or the input-to-output ratio of a workload.

15 linksmetric

Cost per task

Cost per task is the dollar cost of getting a unit of work actually completed by an AI system, measured at a given quality level, rather than the price per token or the score on a benchmark.

needed by 1 · 30 linksconcept

Working memory

Working memory is an agent's capacity to hold and update task state across steps, whether kept in the model's context or externalised into files, logs and maps that the agent builds as it goes.

needed by 1 · 11 linkstechnique

Dreaming

Dreaming is the practice of having one agent inspect another agent's completed work and write memories back for future use.
