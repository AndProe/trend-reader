Smart model routing

first seen 2026-W16 · 12 links · 3 min read

Most requests an AI system receives are easy. Smart model routing exploits that by putting a decision in front of the model call: a small, fast model classifies the request and either answers it or forwards it to a larger, more expensive one. In practice a local model might handle eight of thirty-one incoming emails outright and defer the rest, or a router might send simple agentic jobs to local models and complex ones to a cloud frontier model.

For an executive routing is the cost lever that does not require changing vendors. Companies report large savings through open-source routers, marketplaces such as OpenRouter and in-house routers such as Ramp's sell it as a product, and coding tools have built their own. The condition is evidence: routing is safe only when the organisation knows which tasks the cheap model clears, so it depends on an evaluation programme. Routing also creates resilience, since one API in front of many backends survives any single provider's outage or price change.

Also seen as model routing, Ramp Router, routing to open models

Deeper dive

How it works. A router is a classifier plus a policy. The classifier reads the request, sometimes with a small model as the decider, and estimates difficulty, domain or risk; the policy maps that estimate to a backend, from a local open-weight model through mid-tier cloud models to a frontier model. Open-source gateways such as LiteLLM and marketplaces such as OpenRouter implement the pattern across providers behind one API. The deferral variant lets the small model act on what it is confident about and pass the remainder upward, which is how a local model can clear the majority of a workload. Research on enterprise coding agents identifies where routing can safely happen inside an agent loop, with sub-agent launch as one of three safe switching points, since switching mid-task can lose state. Open weights models are the prerequisite because they supply the cheap tier.

Why it matters now. Routing is reported as the second-largest cost lever in enterprise deployments, with a large telecommunications firm's savings coming through a gateway router and a ride-hailing company routing sub-agents to cheaper models for smaller tasks. Fast, cheap decision models have made the dispatcher itself nearly free, and the common architecture across many new use cases is to send the decision to the cheap model and keep generation elsewhere. Routing is also the mechanism behind local-model cost ceilings: sending each query to whichever local model handles it best captured roughly ninety percent of quality in one measured setting, which changes Cost per task arithmetic and the Price elasticity of frontier demand.

Trade-offs. A router is only as good as its classifier, and misrouting a hard request to a weak model produces a confident wrong answer. Building the evidence base of which tasks each tier clears is an evaluation cost most organisations underestimate. Routing across vendors weakens the case for deep integration with any one of them, which is the tension with a Model-agnostic architecture that abstracts models entirely, and it complicates data governance when requests flow to multiple providers, including Neo clouds hosting open models. Vendors also sell routing, so some of its advocacy is a pitch.

What to watch. Whether routers learn from outcomes rather than fixed rules, how On-device inference shifts the cheap tier onto the user's hardware, and whether frontier vendors respond with pricing that undercuts the routing case.

Related terms

concept

Open weights models

Open weights models are AI models whose trained parameters are published for anyone to download, run and modify, in contrast to closed models reachable only through a vendor's API.

needed by 11 · 36 linksmetric

Cost per task

Cost per task is the dollar cost of getting a unit of work actually completed by an AI system, measured at a given quality level, rather than the price per token or the score on a benchmark.

23 linksconcept

On-device inference

On-device inference means running a language model on the user's own hardware, whether a laptop, a phone, a robot or an on-premise server, instead of calling a cloud API.

needed by 1 · 13 linksconcept

Price elasticity

Price elasticity is the degree to which demand for a model or AI service changes when its price changes.

4 linksconcept

Neo clouds

Neo clouds are GPU-rental cloud providers outside the hyperscalers, such as CoreWeave and the inference hosts Together, Fireworks, Modal and Baseten, that lease accelerators and serve open models.

8 linksmodel

Jev

Jev is TypeSafe AI's decision model, released on 15 September 2026, which takes a state and a set of options and returns a typed, calibrated choice with a confidence score in a single parallel pass instead of generating text.
