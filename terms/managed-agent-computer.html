Managed agent computer

first seen 2026-W33 · 9 links · 3 min read

A managed agent computer is a cloud machine that a vendor spins up for an agent and keeps running. The agent has its own browser, file system and tools there, and the user can open a view of it to see what the agent is doing. Grok Bot uses this as its default, giving each agent an independently viewable computer; the coding agents Codex and Cursor default instead to running on the user's own machine. Several agent products sell the computer layer bundled with the harness.

For an executive the choice is about convenience against control. A hosted machine removes setup, lets agents run for days without a laptop open, and makes long tasks feasible. The cost is that company logins, documents and sessions now live on a vendor's infrastructure, and in practice bots on shared hosted machines end up sharing credentials. Procurement should treat the managed computer as a new tier of infrastructure with its own data-residency, access and audit requirements, not as a feature of a chat product.

Also seen as hosted agent computer, virtual computer, cloud-first agent OS

Deeper dive

How it works. The vendor provisions a virtual machine per user or per agent, with a desktop or headless environment, a browser, a shell and persistent storage. The agent operates inside it through computer-use and tool calls; the user sees a live view and can intervene. Persistence is the defining feature: the machine survives between sessions, so the agent's downloaded files, installed tools and logged-in accounts remain available. This contrasts with ephemeral Remote sandboxes, which are created per task and destroyed afterwards, and with local-first agents that run on the user's hardware and inherit its permissions. Products such as Grok Bot make the managed machine the default; several agent vendors sell it together with their harness.

Why it matters now. Long-running agents need somewhere to live. A Personal agent workflows pattern in which an agent monitors mail, drafts documents and files tickets over days is impractical if the agent dies when a laptop sleeps. The managed computer makes the always-on agent an ordinary product rather than an infrastructure project, and it gives the vendor a full view of the agent's activity for debugging and safety. Computer-use benchmarks such as OSWorld measure exactly the capability these machines exercise: full cross-application operation of an operating system.

Trade-offs. The convenience is bought with a weakened perimeter. Credentials that an agent needs are stored on the vendor's machine, and reports from users of hosted bots describe agents sharing logins, which cuts against Agent security boundaries built on per-identity access. Data residency becomes a contract question. A persistent machine is also a persistent target: anything that compromises it inherits every session the agent has ever opened. Local-first designs avoid these problems but push setup and uptime onto the user, and vendors who merge coding agents into consumer assistants face the same fork.

What to watch. Per-agent identity and credential isolation on hosted machines, enterprise offerings with audit logs and residency controls, and whether the local-first coding agents adopt hosted machines for long tasks.
