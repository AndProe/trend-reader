Generative video

first seen 2026-W35 · 10 links · 3 min read

Generative video models produce moving images, and now sound, from text, images or user actions. The first generation made short clips offline; the current shift is toward generating frame by frame fast enough for a user to interact with, which requires a different model design and a large inference budget. The line between a video model and a world model is counterfactual generation: a world model can render an equally plausible outcome for the action the user did not take.

For an executive, the relevance is threefold. Media and marketing teams can already buy controllable clip generation from providers such as Google's Gemini Omni line, so the near-term question is process and rights, not feasibility. Interactive video points to games, training simulations and product visualisation as the next markets. And the compute bill is dominated by inference, so any plan for real-time video needs a per-user cost model before a product model.

Also seen as video generation, text-to-video

Deeper dive

How it works. Most video generators are diffusion models: they start from noise and denoise a whole clip at once, attending bidirectionally across all frames so that motion stays consistent. That produces high quality but only after the full clip is computed, which rules out interaction. The alternative is an autoregressive model that emits one frame at a time conditioned on the frames before it and on user input. The engineering path now in use is to train a bidirectional diffusion model, convert it into an autoregressive form, then distil it so each frame can be produced within a frame budget.

The shift to real time. Real-time generation turns video from a media format into a simulation. The distinguishing property is counterfactual generation: given a user action, the model should render the outcome, and given the action not taken, it should render an equally realistic alternative. That is the working definition of a world model, and it is what separates interactive video from a clip generator. It is also the underlying capability behind Prompt-to-game products. Each frame costs inference, so this is a direct consumer of Inference-time compute, and the design tension is the familiar one in Interactivity versus throughput: batching frames improves efficiency, latency demands otherwise.

Trade-offs and open problems. Autoregressive generation accumulates error: small artefacts in one frame condition the next, and over long horizons the scene drifts. Keeping a persistent scene state, a form of Working memory for the model, is the main mitigation under research. Distillation and Quantization cut cost per frame but trade away fidelity. On the product side, controllability lags capability: providers are still adding fine-grained control over camera, subject and audio. Provenance is a live question too, since synthetic footage is now cheap to produce.

What to watch. Whether interactive video reaches consumer frame rates on commodity hardware. Whether error accumulation is solved by architecture or masked by periodic re-anchoring. And how quickly the major labs fold video into general multimodal models rather than selling it as a separate product line.

concept

Inference-time compute

Inference-time compute is computation spent when a model answers, through longer reasoning, multiple candidate answers, verification or tool calls, rather than during training.

Quantization

Quantization reduces the numeric precision of a model's weights and activations after training, for example from 16-bit to 8-bit or 4-bit formats, so that it uses less memory, bandwidth and energy.

7 linksconcept

Interactivity versus throughput

Interactivity versus throughput is the trade-off every inference system sits on: raising the tokens per second a single user receives lowers the total tokens a GPU can serve, by roughly thirty times throughput for a tenfold gain in speed.

needed by 1 · 10 linksconcept

Prompt-to-game

Prompt-to-game is the capability of a model to produce a complete, playable game from one or two natural-language prompts, supplying code, assets, mechanics and visual design without further instruction.

4 linksconcept

Working memory

Working memory is an agent's capacity to hold and update task state across steps, whether kept in the model's context or externalised into files, logs and maps that the agent builds as it goes.

AI text watermarking

Hidden statistical patterns embedded in model output at generation time so that a cooperating detector can later identify it as machine-produced.
