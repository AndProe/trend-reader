Test-time adaptation

first seen 2026-W36 · 7 links · 3 min read

Test-time adaptation means a deployed model changes its behaviour in response to what it encounters during use, rather than staying fixed after training. The change can live in context, where the model conditions on interaction history, or in weights, where a small parameter set is updated. Research treats adaptation from human interaction as the practical case, and some methods add stability checks so the model does not drift on unreliable signals.

For an executive, this is the mechanism behind personal agents that improve for a user over weeks rather than resetting each session. It raises three questions: where adapted state is stored and who owns it, how to prevent a model from learning bad habits from noisy interactions, and how to audit a system whose behaviour differs per user. Vendors that offer personalisation will increasingly be doing some form of this, and the governance burden shifts to the deployer.

Also seen as TAHI, adaptation from interaction

Deeper dive

How it works. The model receives a stream of interactions and uses them to alter its future outputs. In the in-context form, history is retrieved and placed in the prompt, which requires no parameter change but grows with use. In the in-weights form, a bounded set of parameters, often a task embedding or adapter, is updated on the fly; one line of research on ARC-like tasks keeps the adaptable parameters small enough to probe and interpret, so the adaptation itself can be inspected. Human-AI interaction methods aim to make this efficient, extracting preference and correction signals from ordinary use rather than requiring explicit feedback rounds.

Why it matters now. Test-time training is the general principle; adaptation from interaction is where it meets products. Persistent agents that remember, personal workflows that accumulate conventions and memory systems that separate long-term state from reasoning all depend on some adaptation mechanism, and the research is converging on making it stable. Stability-aware variants add checks beyond model confidence, because confidence-based adaptation can reinforce errors when the model is confidently wrong.

Trade-offs. Adaptation improves fit at the cost of predictability. A per-user parameter set creates per-user behaviour that is harder to evaluate, and adapted state raises the same retention and portability questions as any stored personal data. In-context adaptation keeps weights fixed but competes with Working memory for the same context budget. In-weights adaptation is compact but opaque unless the parameter set is deliberately kept interpretable.

What to watch. Whether frontier vendors expose adaptation as a product feature or keep it internal, how Personalized agents handle a user's adapted state across devices and providers, and whether interpretable adaptation parameters become a requirement for enterprise deployment. The connection to Continual learning is the open research question: adaptation that persists and compounds is continual learning by another name.

Working memory

Working memory is an agent's capacity to hold and update task state across steps, whether kept in the model's context or externalised into files, logs and maps that the agent builds as it goes.

Continual learning

Continual learning is the ability of a model to keep learning from its deployment, updating on new tasks, users and information while retaining what it already knows, instead of being frozen at the end of training.
