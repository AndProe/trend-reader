Formal verification

Testing shows that software behaved correctly on the cases someone thought of. Formal verification shows that it cannot behave incorrectly on any case, within the properties stated. The method has existed for decades and has been confined to a narrow set of domains for one reason: writing proofs is enormously expensive in expert human time.

That constraint is the thing that changed. Model-generated proof has produced machine-checked safety proofs across more than a hundred open-source libraries in a single reported effort, covering on the order of a hundred million lines of proof code and surfacing bugs that ordinary testing had missed. In a separate reported case, formalising a substantial mathematical result consumed about a week, roughly $135,000 of tokens at ninety percent cache reads, and produced about 600,000 lines of proof. Those are the first unit prices this vault holds for the activity — and they put it inside a startup's roadmap rather than outside it.

Also seen as machine-checked proof, proof-carrying code, autoformalization

Deeper dive

How it works. Properties are stated in a formal language, and a proof assistant mechanically checks that an implementation satisfies them; the proof, not the test suite, is the artefact. The agent-assisted pattern that has emerged is two-phase: produce a plan — in one reported case a high-level human-readable version plus a detailed plan of atomic steps following existing literature — then execute it with an orchestrating agent delegating to agents that do symbolic work, write proof code, and check progress. Notably little scaffolding was reported beyond the plan plus skills distilled from earlier attempts, which makes the plan the expensive part rather than the proving.

Why it matters now. The cost collapse changes which problems get attempted at all, and that is the claim worth taking seriously: formalisation was previously so expensive in human time that few did it and nobody integrated it into a research or engineering roadmap. The security case arrived at the same time — a week in which agent-written code volume, vulnerability discovery and patching pressure all rose together is exactly when proof rather than testing becomes attractive, because the gate on software has historically been whether it worked rather than whether it was secure against every privilege escalation.

Trade-offs. A proof establishes only the properties stated, so specification error replaces implementation error as the failure mode — and nothing in a model-generated pipeline guarantees the properties were the right ones. Proof artefacts are large and must be maintained alongside the code they describe. Cost has fallen but not to zero: six figures of tokens for one mathematical result is cheap against expert time and expensive against a test suite. And the economics depend on cache efficiency, so published prices are sensitive to how a provider charges for repeated context.

What to watch. Whether machine-checked proof appears in security-critical open-source libraries as a matter of course, whether anyone publishes the specification-error rate, and whether proof generation becomes a standard step in agent-written code rather than a separate project.

Models producing new mathematical results rather than reproducing known ones, most visibly the prime-gap bounds attributed to GPT-6 Astra and the Navier-Stokes proof that followed a week later.

Automated software maintenance

Automated software maintenance is the use of coding agents to do the upkeep of a codebase, such as fixing bugs, removing technical debt, upgrading dependencies and re-architecting, without a human driving each task.

Agent reliability

Agent reliability is whether an agent completes a given workflow acceptably often enough to be trusted with it, measured as a target such as success on nearly every run under a defined oversight policy and cost, rather than as a best-case capability score.

Self-verification

Self-verification is an AI system checking its own work before declaring it done, either inside the model's reasoning or through a harness that runs tests, reads telemetry, inspects screenshots and selects among candidate answers.
