Coding harness

first seen 2026-W25 · needed by 9 · 28 links · 3 min read

A raw language model can only answer prompts. A coding harness gives it hands: it feeds the model the right files, lets it run commands, captures the results, keeps the working context under control and loops until the task is done. Claude Code, Codex, Cursor and Devin are harnesses; so is Inspect, the in-house agent Ramp built on the open-source OpenCode harness. The same pattern is spreading beyond code into legal, customer-service and finance products, where the harness is the application and the model is an input.

For an executive the harness is where several decisions now sit. It determines vendor dependence, because the lab-built harnesses are single-model and the open ones can swap models. It determines cost, because harness design drives token consumption, and governance tools now sit under the harness as a proxy to route and meter work. And it determines margin for the companies that build them: the gap between harness price and model cost is a recognised opportunity, reflected in high revenue multiples.

Also seen as AI harness, harnesses, AI coding harness, aftermarket harnesses, open source harness

Deeper dive

How it works. The harness is a control loop. It assembles context from the repository and prior steps, prompts the model, parses its output into tool calls, executes them in a sandbox, feeds results back and repeats. Around that loop sit context compaction for long tasks, permission and safety checks, test-verify-revise scaffolds that fail closed when tests do not pass, and sub-agent delegation. Empirical work now decomposes harnesses into components and measures each one's contribution, and one clear finding is that much of the cost and quality variation in long-horizon runs comes from the harness rather than the model. The discipline of designing these loops is Harness engineering.

Why it matters now. The agentic era is dated from the point at which model-plus-harness products such as Claude Code and Codex began doing end-to-end engineering work. Since then the harness has become the product unit and the commercial control point. Enterprise tooling now positions itself under the harness as an API proxy to route requests across models and govern spend, and the measured cost of swapping one harness for another on coding benchmarks has become a business metric. The pattern has been extended beyond code: vertical products in law, customer service and finance are described in the same terms, and ChatGPT Work is the Codex harness pointed at non-engineers. A Model-agnostic architecture, where an open harness can adopt a second model class, is the main structural alternative to the labs' closed designs.

Trade-offs. One view holds that harnesses are crutches that shrink as models improve, so investment in them depreciates; the counter-view is that the harness is where domain knowledge, safety and workflow integration live and will persist. Closed harnesses from the labs offer the best integration with their own models and the least portability. Open harnesses offer choice at the cost of tuning effort. Every harness is also the first source of untrusted code in an organisation, which is why Remote sandboxes and permission systems are part of the design rather than an afterthought.

What to watch. Whether Specialised harnesses for non-coding domains match the coding results, how the harness margin evolves as model prices fall, and whether the labs open their harnesses to rival models or keep them as part of Vertical integration of AI labs.
