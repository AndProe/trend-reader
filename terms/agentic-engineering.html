Agentic engineering

first seen 2026-W31 · needed by 1 · 9 links · 3 min read

In agentic engineering the division of labour is explicit. Agents write every line, run tests and lint, and increasingly do exploration, specification and test construction. Engineers design the system, set constraints, write specifications that include how the agent should check its own work, and review outputs. Some companies now state as policy that nearly all their code is agent-generated, and the label extends to specialised domains such as production inference serving.

The term marks a change in what engineering talent is for. Agents magnify skill differences rather than erasing them: with clear success criteria they are highly productive, and without them they are confidently wrong in expensive ways, choosing the wrong interconnect or storage, or blaming the provider after misconfiguring hardware. Hiring shifts toward people who can specify and verify, language choice stops constraining hiring if the agent removes the learning curve, and review and observability become the investment that separates a productive team from a pile of unverified code.

Also seen as engineered agent work

Deeper dive

How it works. The workflow inverts the traditional one. The engineer starts from a specification that states the goal, the constraints and, critically, the checks the agent must pass, from test suites to performance budgets. The agent, running in a Coding harness, explores the codebase, proposes a design, writes code and tests, and iterates against the checks. The engineer reviews the result at the level of architecture and intent rather than line by line, and feeds failures back as tighter constraints. At scale this becomes Loop engineering: designing the loop of generation, verification and review so it runs with as little human time as the risk allows. Observability over what agents did, and why, replaces reading the diff as the main control.

Why it matters now. The practice has moved from individual developers to company policy. One well-known software company has stated that agents now generate nearly all its code, and coding-agent vendors report that their own tools do most of the work of building the next version. The evidence on outcomes is mixed in an instructive way: agents excel when success criteria are precise, and fail confidently when they are not, so the skill of the engineer who specifies and verifies matters more, not less. The ability to keep up with Automated software maintenance, where agents handle dependency upgrades and re-architecture, depends on the same discipline.

Trade-offs. The gains in throughput are real, but the failure mode is silent: code that passes the checks the engineer thought to specify and fails on the ones they did not. Review capacity becomes the bottleneck, and a team that cannot review at the rate agents produce accumulates unverified code. The practice also changes career paths, since junior engineers historically learned by writing the code that agents now write, and the Engineering culture question of how to grow judgement without that apprenticeship is open. Language and framework choices become less constrained but also less examined.

What to watch. Whether company-wide agent-generated codebases hold up over years of maintenance, which no organisation has yet demonstrated. Whether specification and verification skills become formally taught and hired for. And whether measures of AI productivity move from lines produced to defects avoided, which is the metric the discipline actually optimises.

Related terms

technique

Coding harness

A coding harness is the software layer wrapped around a language model that turns it into a working coding agent: the loop that manages context, calls tools, runs tests and decides what to do next.

needed by 9 · 28 linkstechnique

Harness engineering

Harness engineering is the practice of designing the tooling, prompts, permissions and feedback loops around a model so that the model performs reliably on real tasks.

needed by 2 · 9 linkstechnique

Loop engineering

Loop engineering is the practice of designing systems in which an AI agent prompts, executes, tests and verifies its own work repeatedly until a stopping condition is met, so that the human designs the loop rather than writing the code inside it.

needed by 1 · 8 linkstechnique

Observability

Observability is the practice of instrumenting software so that its behaviour in production can be understood from the telemetry it emits, and it now covers agents as well as services: wide events in place of logs and metrics, traces of hours-long agent runs, and instrumentation added by default.

needed by 2 · 8 linkstechnique

Automated software maintenance

Automated software maintenance is the use of coding agents to do the upkeep of a codebase, such as fixing bugs, removing technical debt, upgrading dependencies and re-architecting, without a human driving each task.

AI productivity

What the gain from working with AI actually consists of: whether it cuts human effort, raises the quality ceiling at constant effort, or simply adds machine runtime that a person still has to supervise.
