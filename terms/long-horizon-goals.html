Long-horizon goals

first seen 2026-W36 · needed by 1 · 12 links · 3 min read

A long-horizon goal is an instruction such as "solve this problem" or "ship this feature" that an agent works toward for hours or days, planning, executing, checking and revising without a person steering each step. The capability was made concrete by GPT-6 Astra's goal command, which lets a thread run for days, and by reports of an 88-hour multi-agent run on a single mathematical problem.

For an executive this is the point where agents stop being fast assistants and start being delegated workers. It changes the budget question from cost per query to cost per outcome, and it changes the risk profile: an agent that runs for days accumulates context, takes many irreversible actions and can go wrong at a single decision point hours before anyone looks. Adoption is being driven by exactly this mode, so the governance question is how much autonomy to grant and at what checkpoints a person must review.

Also seen as goal runs, multi-day runs, /goal runs

Deeper dive

How it works. A long-horizon run combines a persistent goal, a loop that plans and re-plans, tools that act on the world, and a mechanism to keep context coherent as it grows. GPT-6 Astra exposes this as a goal command that keeps a thread alive for days; the agent spawns Sub-agents, compacts its own history, and returns when it judges the goal met. The reported 88-hour multi-agent run on a single problem, and the work behind the Navier-Stokes proof, are the reference cases for what the mode can produce. Practitioners note that newer models need the explicit goal command less, treating it as a crutch, which suggests the behaviour is moving from harness into model.

Why it matters now. Days-long threads are reported as the main driver of adoption for agentic software tools, because they change what a single person can delegate. Pre-deployment evaluations of frontier models now specifically record qualitative weaknesses on difficult long-horizon tasks, which makes the horizon a formal evaluation axis. Research on agent training treats multi-turn, context-dependent interaction as the target setting, with turn-level weighting and taste over long tasks as active topics. The commercial framing, an automated engineer hired by the hour, only makes sense if the engineer can hold a goal for a working week.

Trade-offs. The same runs are where agents are most brittle. One study localises the difficulty to specific decision points within the horizon rather than to its length, meaning a single wrong branch early on can waste days of compute and produce confident, wrong output. Context rot degrades judgement as the thread grows, and Model persistence across sessions raises the question of what state carries over and who audits it. Cost is open-ended: a goal run has no natural token budget, so spend controls must be set externally.

What to watch. Evaluation suites that report success by horizon length, tooling for checkpoint review inside multi-day runs, and whether labs publish failure analyses of goal runs alongside their successes.

Sub-agents

Sub-agents are parallel agents spawned inside a single run under a coordinator, each given a slice of the task and its own context, with results returned to the parent.

Context rot

Context rot is the degradation of an AI agent's performance and memory reliability as its conversation history accumulates, even when the total stays within the model's nominal context window.

Model persistence

Model persistence is a model's disposition to keep pursuing a goal without giving up, treated as both a capability and a risk factor.
