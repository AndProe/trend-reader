Agent security boundaries

first seen 2026-W32 · needed by 1 · 15 links · 3 min read

A security boundary for an agent answers three questions: what it can touch, in whose name, and who can see what it did. The mature answer extends zero trust from employees to agents. Each agent gets its own identity and scoped credentials rather than a shared login, holds the minimum permissions its task needs, runs under network, file-system and execution limits enforced outside the model, and is monitored end to end with circuit breakers. Authorisation stays outside the model, because anything it reads can try to talk it into misusing what it holds.

A consumer bot product ran several agents on one shared computer with shared logins. A research organisation found its principles of centralised identity, isolation and minimal scoping sound, but a personal instance had sat outside them. The budget decision is to build boundaries into the agent platform before agents proliferate: a coding agent must never touch the production database, and a retailer can block outside agents only if it can tell them apart.

Also seen as zero trust for agents, agent permission model, agent control plane

Deeper dive

How it works. Boundaries are enforced in layers outside the model. Identity: each agent is a principal with its own credentials, so actions are attributable and revocable. Permission scoping: least privilege per task, with authorisation checks that inspect tool permissions and system state before execution rather than trusting the model's judgement. Isolation: network, file-system, user-interface and execution limits expressed as containment policies, with proxies that can inspect tool-protocol payloads in transit. Monitoring: end-to-end logging with circuit breakers, modelled on insider-threat controls. The design principle is that the front end, the web content and any document the agent reads are untrusted, and the boundary sits where untrusted content shares a context with system instructions.

Why it matters now. Agents have live access to terminals, browsers and files, which dissolves the classical perimeter; once a process has execution authority, network position no longer defines what it can reach. Prompt injection means a boundary is a property of the interaction, not of the model, so no amount of model alignment substitutes for external enforcement. Multi-agent settings add cross-agent manipulation, where one compromised agent instructs another. Consumer products that share a computer and logins across bots, and organisations whose personal instances sat outside their controls, show how easily the principles are skipped. The broader programme is AI agent containment, of which boundaries are the enforcement layer, and it depends on Agent identity and Agent accountability to work.

Trade-offs. Tight boundaries reduce usefulness: an agent that cannot reach a system cannot fix it, and every approval gate adds latency and human cost. Boundaries also have known gaps. Gates and permissions cannot reject a call to a tool that does not exist, so tool hallucination bypasses permission systems until the harness resolves calls against a closed catalogue. A Sandbox escape defeats isolation, and monitoring only helps if someone acts on it. Applying the same limits to every agent ignores that Blast radius differs by task, which argues for graduated policies rather than a single setting.

What to watch. Whether operating systems and cloud platforms ship containment policies and agent-aware proxies as defaults, which would move boundaries from bespoke engineering to configuration. Whether agent security benchmarks that measure dual-control and manipulation scenarios enter procurement. And whether Shadow AI agents running outside sanctioned boundaries are treated as an enablement problem, by making the sanctioned path easier, or a purely security one.

Shadow AI

Shadow AI is the unsanctioned use of personal AI tools by employees for work, the AI-era version of shadow IT and often called bring your own AI.

Sandbox escape

A sandbox escape is an agent getting past the isolation it was given, whether by exploiting a flaw in the sandbox itself or, far more often, by using a misconfiguration such as an allow-listed proxy that permits writes or a package mirror that reaches the internet.
