Vibe coding

first seen 2026-W17 · 13 links · 3 min read

Vibe coding is software by conversation: describe what you want, let the agent write it, run it, and keep prompting until it works. It has spread from hobbyists to marketing teams opening pull requests, in-house portals built in a day, and firms claiming hand-written code has ended for professional work. Labs use the phrase themselves for voice-driven app building.

For an executive, the opportunity is real and so are the failure modes. Apps that work on the builder's laptop fall over at contact with users: databases that cannot scale, fail-open authentication that attackers find through certificate transparency lists, vendor choices nobody can explain, and deployments that were never reachable by anyone else. The practical governance question is where vibe-coded software is acceptable, judged by consequence and ownership, and whether the people prompting it know enough to ask about auth, storage, deployment and blast radius. Discarded prototypes are cheap; production systems built the same way are not.

Also seen as vibe-coded apps, vibe coders, prompting an app into existence

Deeper dive

How it works. The builder describes an outcome and the agent selects the language, framework, database, hosting and authentication approach, usually without the builder examining the choices. Iteration is by observation: if the result looks wrong, prompt again. Because the agent optimises for a working demo, it favours defaults that are quick rather than durable, and the builder inherits a system they did not design. Designers have turned the same mechanism into a tool, asking for tweakable prototypes rather than specifying values, which treats the agent as a design instrument rather than a shortcut. The Coding harness the builder uses determines how much of this is visible.

Why it matters now. The practice has crossed into professional settings: non-engineering teams ship code, a company known for its web framework has declared hand-written code over for professional work, and researchers build their own portals and dashboards in a day on the principle that one should build the tools that shape how one thinks. This is the second wave of AI consumption, where usage moves from chat to production of artefacts. At the same time the failure modes are documented across a six-part series on engineering for vibe coders: frontends and backends that were never separated, storage that falls over at scale, missing authorisation, and deployment that never left the laptop. One security update describes fail-open authentication in a vibe-coded application discovered by attackers scanning certificate transparency lists, which shows the gap between working and safe.

Trade-offs. Vibe coding collapses the cost of a first version and expands who can build, but it moves the cost to maintenance, security and scale, where the builder lacks vocabulary. It also produces AI slop in code: plausible, unexplained and hard to review. The contrast with Agentic engineering is discipline rather than tooling: the same agent, with specifications, verification and an engineer who understands the stack. Practitioners propose rules of thumb based on consequence and ownership for when the practice is appropriate.

What to watch. Whether Agent security boundaries and secure defaults in harnesses close the auth and data failures automatically, how Blast radius thinking enters non-engineering teams, and whether the volume of thrown-away projects, invisible to statistics, converts into durable software.

Coding harness

A coding harness is the software layer wrapped around a language model that turns it into a working coding agent: the loop that manages context, calls tools, runs tests and decides what to do next.

Claude Code

Claude Code is Anthropic's terminal-based coding agent: a harness that wraps a Claude model with file, shell and tool access so it can plan, edit, run and verify changes across a codebase on its own.

AI-assisted migrations

The use of coding agents to execute large framework, language, database or test-suite migrations that were previously too expensive to attempt, with retry-and-verify pipelines doing most of the mechanical work.

Agent security boundaries

Agent security boundaries are the permission, identity and network limits that separate one agent's reach from another's and from its operator's, applying zero-trust principles to agents with per-agent credentials, least privilege, isolation and monitoring.

AI slop

Low-effort AI-generated content that costs the reader more than it cost the sender: pitches, pull requests, code shipped by founders who cannot maintain it, drive-by contributions to open-source projects, mass-produced marketing.

Software factory

A software factory is a production system in which agents run the reproduce, fix, review and verify loop end to end, with humans setting the rules and reviewing a fraction of the output.
