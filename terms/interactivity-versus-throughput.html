Interactivity versus throughput

first seen 2026-W33 · needed by 1 · 10 links · 3 min read

An inference server can either serve many users slowly or few users quickly. Batching many requests together keeps the accelerator busy and maximises tokens per GPU, but each user waits longer for each token. Serving fewer requests at once gives each user a fast stream but leaves compute idle. The relationship is a curve, and the numbers are steep: roughly thirty times the aggregate throughput is given up to make one user's stream ten times faster. That is why ultrafast tiers are priced as premium products, and why every hardware comparison must specify the per-user speed at which it was measured.

For an executive, the trade decides what a fast experience costs. Interactive uses such as voice, live avatars and real-time video sit at the expensive end; batch jobs such as document processing sit at the cheap end. Interactive tokens can be worth more than bulk delayed tokens, so pricing by use case rather than by token is the rational response, and hardware choice depends on which end of the curve the workload occupies.

Also seen as latency-throughput trade-off, interactivity trade-off

Deeper dive

How it works. Generating a token requires reading the model's weights and the KV cache from memory. A single request reads them once per token and leaves most of the arithmetic units idle, because the operation is bound by memory bandwidth, not compute. Batching many requests amortises the same read across all of them, so throughput per GPU rises with batch size, but each request's tokens are produced only once per batch step, so per-user speed falls. Plotting per-user tokens per second against tokens per GPU gives a Pareto frontier; the worked examples show that tenfold per-user speed costs about thirtyfold aggregate throughput. Multiples quoted between hardware platforms are taken at a fixed target, often the ninetieth-percentile per-user speed, and the advantage changes along the curve.

Why it matters now. Interactive products are moving to the expensive end. Voice agents, live avatars and near real-time Generative video all need a latency budget that enterprises are now willing to pay for, and the argument from video is that real-time generation wins on both experience and serving cost once the model is built for it. Ultrafast mode and Ultra-low latency tiers are this trade priced explicitly. At the other end, Agentic inference workloads behave differently: they are long, bursty and cache-heavy, and an agent waiting on a tool call does not need a fast stream, so they can be served cheaply in bulk. The same accelerator can be a bargain for one workload and a poor choice for the other.

Where the curve moves. Hardware with more memory bandwidth, and software that fuses kernels to squeeze latency out of each decode step, push the whole frontier outward. Prefill-decode disaggregation lets prefill run on throughput-optimised hardware while decode runs on latency-optimised hardware. Speculative decoding produces several tokens per step and raises per-user speed without proportionally cutting throughput. And Performance per watt adds a third axis, since interactive serving burns power on idle compute.

What to watch. Whether pricing by interactivity becomes standard across providers. Whether disaggregated serving closes enough of the gap that fast modes stop being premium. And how the curve looks on the next accelerator generation, where memory bandwidth is the design target.

Related terms

concept

Ultrafast mode

Ultrafast mode is a paid high-speed inference tier that serves the same model many times faster on specialised hardware, such as OpenAI's Cerebras-backed Ultrafast at roughly 14 to 15 times standard speed.

5 linksconcept

Ultra-low latency

Ultra-low latency is response time measured in milliseconds or microseconds, treated as an engineering property that a product depends on rather than a nice-to-have.

7 linkstechnique

KV cache

The KV cache is the per-token store of key and value vectors that a transformer keeps during generation so it does not recompute attention over the whole context on every step.

needed by 2 · 12 linksmetric

Performance per watt

Performance per watt measures how much useful AI output, typically tokens or benchmark-weighted intelligence, a system produces per unit of electrical power.

11 linksconcept

Generative video

Generative video is the class of models that synthesise video, and increasingly synchronised audio, from prompts rather than editing existing footage.

10 linksconcept

Agentic inference workloads

Agentic inference workloads are the production traffic pattern created by coding and computer-use agents: many turns per task, context that accumulates toward a million tokens, very high reuse of shared prefixes, and bursts of parallel sub-agent calls.
