Specialised harnesses

first seen 2026-W30 · 7 links · 3 min read

A harness is everything around a model that turns it into a working agent: the tools it can call, the instructions it follows, the checks on its output and the interfaces it lives in. A specialised harness fixes all of that for one domain and sells it as a product. The lawyer using Harvey, the clinician using Abridge and the support team using Sierra are all using roughly the same underlying models; the product is the harness.

For an executive this is the build-versus-buy question for AI agents. Three options exist: customise a general harness such as a coding agent with skills and tool connections, buy a specialised harness for the domain, or build a custom harness. The specialised product is the middle path, and its valuation multiples show investors believe the harness rather than the model is where durable margin sits. The risk is dependency on a vendor whose product could be absorbed by the model provider or undercut by a general agent with the right skills.

Also seen as specialized harnesses, domain-specific harnesses, vertical harnesses

Deeper dive

How it works. A specialised harness starts from an Agent harness and hardens each layer for one vertical. Tools are the domain's systems: case databases and document management for law, electronic health records for clinical notes, ticketing and CRM for customer service, the company's own document stores for enterprise search. Prompts encode the domain's conventions and the regulatory language it must respect. Guardrails block outputs the domain cannot tolerate, such as unsupported legal citations or unverified clinical claims. Evaluation is built against domain benchmarks rather than general ones. Because the model is swappable, the harness vendor can move to a better model without changing the product, which is the Frontier models dependency handled as a supplier relationship.

Why it matters now. The category has grown from a few legal and clinical products to a recognised class alongside chat harnesses and coding harnesses, with design tools, code reviewers, sales-data tools and search products all fitting the pattern. It sits in the middle of three options for organisations: customising a general coding harness such as Claude Code with a Skill library and MCP servers, buying a vertical product, or building from scratch. Revenue multiples for harness companies indicate that investors price the harness as the durable layer, on the view that models commoditise and the domain integration does not. The category is part of the broader Harness engineering discipline in which the same work is done in-house.

Trade-offs. A specialised harness delivers domain fit, compliance features and support that a general agent lacks, at the cost of vendor lock-in and a price premium over the underlying model. General harnesses with skills are catching up, since a well-written skill library can encode much of what a vertical product hard-codes, and model providers have shown willingness to move up the stack into products. The Coding harness is the contrasting case: a general tool that becomes specialised through configuration rather than through a separate product. Data also matters, because the vertical vendor sees every customer's usage and can improve the harness in ways an in-house team cannot.

What to watch. Whether model providers acquire or replicate leading vertical harnesses, whether skills-based customisation erodes the category's premium, and how harness revenue multiples hold as models improve.
