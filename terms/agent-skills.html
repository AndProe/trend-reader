The practical question in agent engineering is where accumulated know-how lives. Prompts are per-run and get lost. Scaffolding is per-project and has to be maintained. Skills sit in between: a packaged description of how to do something, loaded by the harness when relevant, reusable across runs and shareable between teams.

The evidence that this works is unusually concrete. A substantial formalisation effort reported needing little scaffolding beyond an initial plan plus skills distilled from the team's earlier attempts at the same kind of work — meaning the skills, not the harness code, carried the institutional learning. On the product side, a harness vendor ships a skill that teaches the model how to write extensions for the harness itself, so a user can request an interface change in plain language and have the model build it. That is a skill bootstrapping the system that loads skills.

Also seen as skills, agent skill packs

Deeper dive

How it works. A skill is content rather than code: instructions, procedures and worked context that a harness injects when the task calls for it. That distinguishes it from a tool, which is an executable capability, and from a plugin, which modifies the harness's own behaviour — though the boundaries blur when a vendor ships skills, tools and plugins through one mechanism. Distribution has started to standardise, with skills donated to a neutral foundation and interoperating with tool-exposure protocols.

Why it matters now. Skills are the answer to a question several independent findings have pushed to the front: more orchestration does not buy accuracy. An elaborate harness has been measured as statistically equivalent to a minimal one at up to three times the cost, frontier models have been shown managing their own context as well as a leading harness does, and investigative work has been shown to depend on supplying the right index rather than more machinery. If the model does not need more scaffolding, what it needs is better-prepared knowledge — which is what a skill is.

Trade-offs. Skills consume context, so a library large enough to be useful competes with the work itself and needs routing, which is the same selection problem Dreaming and adapter libraries face. They also encode assumptions that go stale as systems change, with nothing in the loop detecting contradiction. And a skill that teaches a model to modify its own harness is a capability with an obvious dual use: the thing that lets a user shape their interface is the thing that lets an agent reshape the layer meant to supervise it.

What to watch. Whether skill formats converge across harnesses, whether skills acquire versioning and retirement, and whether published agent results begin attributing gains to skills rather than to models.

Related terms

technique

Agent harness

An agent harness is everything around the model that lets it operate a system: the tools it can call, the permissions it holds, the loop that decides when to act again, the environment it runs in and the checks applied to its outputs.

MCP

MCP, the Model Context Protocol, is an open standard for exposing tools, data sources and device controls to AI agents through a uniform server interface.

9 linksconcept

Agent interoperability

Agent interoperability is the ability of agents built by different vendors to work together across a shared platform or protocol, exchanging tasks, results and context without custom integration.

7 linkstechnique

Dreaming

Dreaming is the practice of having one agent inspect another agent's completed work and write memories back for future use.

15 linkstechnique

Continual learning

Continual learning is the ability of a model to keep learning from its deployment, updating on new tasks, users and information while retaining what it already knows, instead of being frozen at the end of training.

12 linkstechnique

Skill library

A skill library is a store of reusable, named procedures that an agent can load and apply, whether taught by demonstration, written by hand as instructions, derived from failure diagnoses or compiled into executable artefacts.
