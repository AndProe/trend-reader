Context rot

first seen 2026-W30 · 9 links · 3 min read

Language models can accept very long inputs, but they do not use all of that input equally well. As an agent works through a task, its context fills with earlier tool outputs, abandoned attempts, stale file contents and conversational residue. Past a certain point the model starts to lose track of what matters, repeats itself, or acts on outdated information. That decline is context rot. Practitioners describe a smart zone and a dumb zone, and portion work so that a session stays under roughly 150,000 tokens.

For an executive the term explains a class of agent failures that look like randomness and are not. It sets a practical limit on how long an agent should live before it is restarted, which affects how work is broken up, how memory is stored between sessions and how much a long task costs. It also explains why harness quality matters as much as model quality: the tooling that keeps the context clean is what keeps the agent in the smart zone.

Also seen as context degradation, long-session decay

Deeper dive

How it works. A model's attention over a long context is not uniform, and the useful signal in an agent's history is diluted by everything that was tried and discarded. Three failure modes are named in the research. Context overflow, where the history simply exceeds what the model can hold, is the crude case and is mostly prevented by harness context management. Accumulated context drift, where repeated summarisation compounds errors, is subtler; one compaction method adopts the rule of never compacting a compaction, so summaries are always built from original material. And stale evidence, where the context contains conflicting versions of a file or fact, is increasingly treated as a property of the environment the agent works in rather than of the session itself. All three degrade Working memory and make the agent's behaviour depend on how the context was assembled.

Why it matters now. Agents now run for hours across millions of tokens, so the question of how long an agent should live has become a design decision rather than a curiosity. Long context windows did not solve the problem; they moved it, because a larger window rots more expensively. Harness designers respond with compaction, with portioning work into sub-tasks that each start clean, and with external memory that persists between sessions, which is the territory of Persistent agents. The KV cache economics of long contexts add a cost dimension, since a rotting context is also an expensive one to keep cached.

Trade-offs. Aggressive compaction keeps the context lean but loses detail the agent may later need. Frequent resets avoid rot but discard learning within the session, which is why Continual learning and cross-session memory are studied as complements. External memory that survives across sessions introduces its own risk, since anything written to it can be corrupted, the concern behind Memory poisoning. And the 150,000-token rule of thumb is empirical and model-specific; it will shift as models and harnesses change.

What to watch. Whether long-horizon benchmarks begin to measure degradation over a session rather than final success alone, whether models are trained specifically to resist rot, and whether the never-compact-a-compaction rule and similar harness disciplines become standard.

Related terms

concept

Long context

Long context refers to model context windows of hundreds of thousands to a million tokens, which allow an agent or a user to place entire codebases, document collections or multi-hour recordings in front of the model at once.

needed by 4 · 12 linksconcept

Working memory

Working memory is an agent's capacity to hold and update task state across steps, whether kept in the model's context or externalised into files, logs and maps that the agent builds as it goes.

7 linksconcept

Persistent agents

Persistent agents are AI agents designed to run continuously and carry memory, identity and relationships across sessions, devices and tasks, instead of starting fresh on each request.

needed by 2 · 16 linksconcept

Memory poisoning

Memory poisoning is the compromise of a long-lived agent through its persistent context: a malicious email, document, calendar invite or retrieved record plants instructions or false facts that the agent carries forward into later actions.

6 linkstechnique

KV cache

The KV cache is the per-token store of key and value vectors that a transformer keeps during generation so it does not recompute attention over the whole context on every step.

needed by 2 · 12 linkstechnique

Continual learning

Continual learning is the ability of a model to keep learning from its deployment, updating on new tasks, users and information while retaining what it already knows, instead of being frozen at the end of training.
