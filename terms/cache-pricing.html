Cache pricing

first seen 2026-W36 · 6 links · 3 min read

When an application sends a model the same long instructions, documents or conversation history on every call, the provider can keep the processed form of that text in memory and charge much less to reuse it. Cache pricing is that reduced rate. With the Fable 5.1 release Anthropic cut cache reads by 75 percent to $0.25 per million tokens while leaving its headline per-token prices unchanged, and a later 60 percent cut applied to Opus 5.5 cache reads. The claimed 25 to 45 percent saving for customers sits almost entirely in this line of the price sheet.

For an executive this changes how to read a vendor quote. Two providers with identical list prices can differ by half in real cost depending on cache terms, because in agentic runs the majority of input tokens are repeats. Any payback calculation for AI coding agents or enterprise assistants should model cached and uncached tokens separately, and procurement should treat cache-read rates as a primary negotiating term.

Also seen as cache read pricing, cache reads, caching discount

Deeper dive

How it works. A transformer processes a prompt into a KV cache, the internal state that attention reads from. Recomputing that state for an unchanged prefix wastes GPU time, so providers store it and, when the same prefix arrives again, skip straight to the new tokens. The saving is real engineering cost, which is why providers can price cache reads at a fraction of fresh input. The cached share of input tokens in an agentic run is high because each step re-sends the system prompt, tool definitions and accumulated history, and only the latest turn is new.

Why it matters now. The Fable 5.1 launch made cache pricing the centre of the commercial story. List prices did not move; cache reads fell 75 percent to $0.25 per million tokens, and the marketing claim of 25 to 45 percent savings depends on it. The subsequent price war around Claude Opus 5.5 and the GPT-6 variants repeated the pattern, with a 60 percent cut on Opus 5.5 cache reads. Increased caching is a win for both sides: the provider serves more requests per GPU and the customer pays less per task. It is also becoming an input to enterprise decisions about routing coding agents across models, since the cache terms change the Cost per task more than the base rate does.

Trade-offs. Cache discounts reward stable prompts and penalise applications that rewrite context every call, which pushes harness design toward long-lived, append-only contexts even where that hurts quality through context bloat. Caches expire, so bursty workloads gain less. And because cache terms differ across vendors, comparing offers becomes harder and switching costs rise, which works in the incumbent's favour.

What to watch. Whether cache-read rates converge across providers or become the main axis of price competition, how long providers keep caches warm without charge, and whether Token efficiency improvements in the models themselves reduce the volume of cached tokens enough to blunt the discount's importance. The price sheet for Claude Fable 5.1 is the current reference point.

Related terms

technique

KV cache

The KV cache is the per-token store of key and value vectors that a transformer keeps during generation so it does not recompute attention over the whole context on every step.

Cost per task

Cost per task is the dollar cost of getting a unit of work actually completed by an AI system, measured at a given quality level, rather than the price per token or the score on a benchmark.

Token efficiency

Token efficiency is the amount of useful capability a model delivers per token consumed or produced, whether measured as output tokens per task, accuracy per token, or the input-to-output ratio of a workload.
