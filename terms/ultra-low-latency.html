Ultra-low latency

first seen 2026-W31 · 7 links · 3 min read

Ultra-low latency means a system answers fast enough that the delay does not change the outcome, whether that is a trade executed before the market moves, a game loop that stays smooth or an agent that acts inside a browser race. In trading it has become table stakes rather than the edge. In AI it is the target of persistent-kernel and wafer-scale inference engineering and the basis of the paid fast tiers that vendors now sell.

For an executive, latency is a product property with a price. Faster inference costs more per token and often runs on specialised hardware, so it should be bought only where time changes value: interactive agents, voice, real-time decisions in operations or finance. Where speed is decisive, the framing to remember is a chess clock: under a time limit the faster model wins even if it is less capable, so model selection depends on the time budget as much as on quality.

Also seen as low latency engineering, microsecond latency

Deeper dive

How it works. Latency in an inference system is dominated by the time to first token and the per-token decode time, both governed by memory bandwidth and by how quickly work is dispatched to the accelerator. Techniques that cut it include persistent kernels that keep the model resident and avoid launch overhead, wafer-scale processors that hold weights in on-chip memory, and speculative or streaming designs. The general trade-off is Interactivity versus throughput: serving a single user very fast leaves hardware under-utilised compared with batching many requests, which is why fast tiers cost more. At trading firms latency engineering is mature and now table stakes, with the moat elsewhere.

Why it matters now. Real-time products have arrived. Live transcription and voice variants target sub-second streaming; agents that make millisecond decisions inside game loops and browser interactions are being sold as products; and time-critical decision support in operations names latency as the remaining barrier. Vendors have responded with an Ultrafast mode tier priced above standard inference. In systems languages the same pressure appears: latency now costs money in games and trading, which made the old speed-versus-safety trade-off in language choice untenable and lifted Rust.

Trade-offs. Every millisecond removed costs utilisation, hardware specialisation or model size. Wafer-scale and persistent-kernel serving deliver speed for generation-heavy workloads but help less when the bottleneck is a chain of tool calls. Latency also interacts with quality: a smaller or lower-effort model is faster, so a time budget effectively caps the intelligence available. And low latency at the model does not survive a slow surrounding system, so the KV cache, network path and harness all need attention.

What to watch. Whether fast tiers become standard rather than premium, how Quantitative trading firms adopt models inside their latency budgets, and whether real-time agents establish a market that justifies dedicated inference hardware.

Ultrafast mode

Ultrafast mode is a paid high-speed inference tier that serves the same model many times faster on specialised hardware, such as OpenAI's Cerebras-backed Ultrafast at roughly 14 to 15 times standard speed.

Quantitative trading

Quantitative trading is the business of firms trading their own capital with automated systems built around a watch-decide-send loop, historically won on latency and now increasingly on models.

KV cache

The KV cache is the per-token store of key and value vectors that a transformer keeps during generation so it does not recompute attention over the whole context on every step.

Jev

Jev is TypeSafe AI's decision model, released on 15 September 2026, which takes a state and a set of options and returns a typed, calibrated choice with a confidence score in a single parallel pass instead of generating text.

9 linkstechnique

RLCD

RLCD, reinforcement learning for calibrated decisions, is a training method that teaches a model to answer many typed questions about a single input with calibrated probabilities in one pass, instead of generating text.

Interactivity versus throughput

Interactivity versus throughput is the trade-off every inference system sits on: raising the tokens per second a single user receives lowers the total tokens a GPU can serve, by roughly thirty times throughput for a tenfold gain in speed.
