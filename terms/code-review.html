Code review

first seen 2026-W33 · needed by 1 · 12 links · 1 min read

The human review of changes before merge, now an overloaded ritual under AI-generated volume: product decisions stay human, validation moves to tooling, and some teams treat it as optional.

Also seen as PR review, code review load

AI code review

Models reviewing code changes, multi-model in Greptile's case, and the diff-review habit borrowed back into prose editing; the tooling answer to the review burden AI-generated code creates.

8 linkstechnique

Verification loops

Pipelines that retry and validate each change until it passes tests, the common ingredient in every AI-migration success story and the basis of software factories.

needed by 3 · 14 linksconcept

Closed contributions

Open-source projects refusing external pull requests by policy, or restricting AI-written ones, because drive-by AI contributions overwhelm maintainers.

4 linksconcept

Cognitive debt

The loss of memory, understanding and judgement that accumulates when people accept model output as their own without engaging with it, and the organisational version when experienced engineers are removed without notice.

6 linkstechnique

Automated software maintenance

Agents doing the upkeep work on a codebase, such as fixing bugs, removing tech debt, upgrading dependencies and re-architecting, without a human driving each task.

10 linksconcept

Database schema

The written rulebook of a database, every table, column, type and connection the application code depends on; David Krevitt (Technically) presents schema changes as one of the failure points of a vibe-coded app, with a blast radius set by how defensively the code was written.
