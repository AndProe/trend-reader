Recurrent depth

first seen 2026-W36 · 5 links · 3 min read

A standard transformer runs an input through a fixed stack of layers once. A recurrent-depth or looped transformer runs it through the same layers several times, with the number of loops chosen per token or per query. The model gets deeper thinking for hard inputs without needing more weights, more memory or a longer written scratchpad.

The design reportedly appears in GPT-6 Astra, and it touches two executive concerns. On cost, it is a route to frontier capability with lower capacity requirements, which matters when memory bandwidth and chip supply are the binding constraints. On governance, it moves part of the model's reasoning into a hidden latent state where no one can read it. The lab's own clarification is that Astra's computation-graph depth stays within a factor of two of GPT-4 and that it does not use an unreadable internal language, but the direction of travel is towards models whose thinking is harder to audit, and buyers with oversight obligations should note that.

Also seen as looped transformer, looped-transformer technique, recurrent-depth architecture

Deeper dive

How it works. In a looped transformer a block of layers is applied repeatedly to the residual stream, sharing weights across passes. The lineage runs from the Universal Transformer through recent designs such as Ouro, Nanbeige and Mixture-of-Recursions, and the shared features are a persistent latent state carried between iterations and adaptive computation that decides how many loops a given token receives. The effect is depth on demand: an easy token exits early, a hard one is refined through more passes. This is a form of Inference-time compute, but unlike a long chain of Reasoning tokens the extra work happens in continuous activations rather than in discrete text.

Why it matters now. Reports place the technique inside GPT-6 Astra, where it is described as scaling the model through depth instead of weights and thereby lowering the memory footprint required to serve it. That is attractive in a market where high-bandwidth memory and accelerator capacity are the scarcest inputs. The same property has drawn the attention of safety researchers because Chain-of-thought monitoring assumes the written Reasoning traces are a reasonably faithful account of the model's computation. Looped computation weakens that assumption by construction, and it was singled out as the architectural threat to monitorability, distinct from the self-inflicted threat of training on the chain of thought itself.

Trade-offs. The efficiency gain is real but bounded: latency rises with loop count, and serving systems must handle variable per-token work. On monitorability, the current position is a matter of dose. The stated clarification is that Astra's effective depth remains within a factor of two of GPT-4 and that the model does not use neuralese, so the amount of reasoning that has moved off the trace is described as small enough not to damage interpretability yet. The concern is that the incentive to loop more, since it is cheaper than adding weights, pushes each generation further from readable reasoning.

What to watch. Disclosed loop depth in future system cards, whether interpretability tools can read the latent state between iterations, and whether other labs adopt the architecture, which would make the monitoring question industry-wide rather than specific to one model.
