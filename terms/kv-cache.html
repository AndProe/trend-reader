KV cache

first seen 2026-W34 · needed by 2 · 12 links · 3 min read

In plain terms, a transformer reads a prompt once and writes out a working memory of it, one entry per token. That memory is the KV cache. Every new token the model produces consults it, and without it the model would have to re-read the entire conversation at each step. The cache lives in fast accelerator memory alongside the model weights, and because it grows with every token added, a long agent session can occupy more memory than the model itself.

The executive significance is that the cache has become the unit of cost in agentic serving. Agents append to one growing context for hours, so the fraction of memory devoted to cache decides how many sessions a machine can hold, how much prefix work can be reused between turns, and which model an agent is effectively locked to. Decisions on hardware (memory capacity versus compute), on pricing (cached input tokens are billed differently) and on architecture (whether an agent can switch models mid-task) all turn on it.

Also seen as KV-cache, KV cache capacity, KV cache reuse, key-value cache

Deeper dive

How it works. During attention, each token produces a key vector and a value vector per layer and per attention head. Storing them means the decode step for a new token only computes its own query and reads the stored keys and values, rather than recomputing the whole sequence. The cost is memory: the cache scales linearly with context length, layer count and head dimension, and at hundreds of thousands of tokens it dominates the HBM budget. Serving stacks therefore treat the cache as a first-class object: they lay it out in pages, offload cold pages to DRAM or SSD, and cache shared prefixes so a system prompt or an earlier turn is not re-prefilled. Recent work goes further and treats the cache as an immutable, forward-only blob store that can be moved between machines, or as mutable state that needs budgeted repair when a document in context is edited.

Why it matters now. Agentic inference workloads are defined by prefix reuse: a coding agent's session is one long context to which each tool call appends, and most of the read traffic is cache being fetched from memory rather than fresh computation. That shifts the bottleneck from compute to memory capacity and bandwidth, which is why taller HBM stacks and offloading are debated in terms of how much per-user cache they buy, and why Prefill-decode disaggregation exists at all. On SRAM-based machines the cache is the hard ceiling on Long context. The cache also creates lock-in: appending to one model's cache is what ties an agent to that model, so any router that wants to switch models must respect cache affinity.

Trade-offs. Sparse attention and top-k selection reduce compute but still need to index the full cache, which is why hybrid systems split the work across devices. Reducing the cache itself, as DeepSeek V4.1 Flash reportedly did by cutting its memory footprint to a quarter, lowers serving cost at some quality risk. Test-time training proposes replacing the growing cache with a fixed-size weight update, trading unbounded memory for a lossy summary. Cache-sharing between looped layers has been tried and failed in at least one reported experiment.

What to watch. Cache pricing tiers, cross-machine cache transfer as a standard serving primitive, and whether any fixed-size alternative reaches production quality on long agent tasks.

Related terms

concept

Long context

Long context refers to model context windows of hundreds of thousands to a million tokens, which allow an agent or a user to place entire codebases, document collections or multi-hour recordings in front of the model at once.

needed by 4 · 12 linkstechnique

Prefill-decode disaggregation

Prefill-decode disaggregation is a serving architecture that processes a request's prompt on one pool of hardware and generates its output tokens on another, transferring the KV cache between them.

6 linksconcept

Agentic inference workloads

Agentic inference workloads are the production traffic pattern created by coding and computer-use agents: many turns per task, context that accumulates toward a million tokens, very high reuse of shared prefixes, and bursts of parallel sub-agent calls.

needed by 1 · 16 linkstechnique

Sparse attention

Sparse attention is a family of attention mechanisms in which each token attends to a selected subset of positions rather than to every previous token, so that the cost of long contexts grows less than quadratically.

6 linksmodel

DeepSeek V4.1 Flash

DeepSeek V4.1 Flash is DeepSeek's open-weights model that benchmarks level with Claude Opus 5 and GPT-5.6 Sol, the previous frontier generation.

5 linkstechnique

Test-time training

Test-time training is a model updating its own weights on the input it is currently processing, instead of remaining frozen after training.
