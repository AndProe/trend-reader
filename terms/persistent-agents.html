Persistent agents

first seen 2026-W35 · needed by 2 · 16 links · 3 min read

A persistent agent is one that does not reset. It keeps long-term memory of what it has done and learned, holds a stable identity that other people and agents can recognise, and continues across devices and sessions rather than restarting with each conversation. Monitoring, ambient assistance and multi-day projects all depend on this property, and major platforms now state the continuous assistant as a product goal rather than a research direction.

For an executive persistent agents change the economics and the risk profile of automation. Much of the measured productivity gain from agents comes from work that continues overnight, which means a computer that never sleeps rather than a faster worker. Because such agents spend most of their time idle, per-token cloud pricing fits them poorly and local or flat-rate hosting becomes attractive. The risks concentrate in memory: whatever the agent retains can be poisoned, leaked or subtly wrong for a long time, so governance of agent memory becomes as important as governance of data.

Also seen as always-on agents, continuous agents

Deeper dive

How it works. Persistence rests on three components. The first is memory outside the model: stored facts, preferences and past actions that are retrieved into context on demand, whether as plain files, structured knowledge bases or server-side encrypted stores. The second is identity: a consistent persona and set of commitments that survive across sessions, which recent benchmarks measure as identity fidelity over time rather than simple recall. The third is scheduling: the agent is triggered by events, timers or messages instead of a user prompt, so it needs a host that stays on. Research on long-term memory increasingly separates the memory system from the reasoning model so that the knowledge persists while the model can change.

Why it matters now. The pattern is being built at every layer. Platforms are shipping secure server-side memory so an assistant continues across devices. Self-hosted harnesses such as OpenClaw keep memory in local files, and On-device inference is pitched as the natural home for an agent that runs all day, since a machine already paid for costs nothing per idle hour. Studies of agent productivity attribute a large share of the gain to agents working through the night. Personalized agents are the consumer face of the same idea: adaptation to one user is only useful if it persists.

Trade-offs. Long-lived memory accumulates errors. Context rot degrades performance as retained material grows, and Memory poisoning lets an attacker plant instructions that the agent will act on later. Identity across sessions raises accountability questions, since a persistent agent can build reputation and relationships that outlast any single task, which is why Agent identity has become a precondition for trusting one. There is also a design tension between a stable identity and the need to keep learning, since Continual learning changes the very model the identity depends on.

What to watch. Whether memory standards emerge that let an agent move between hosts without losing itself, how vendors price always-on agents, and whether benchmarks for identity persistence and memory integrity become part of procurement.

Agent identity

Agent identity is a verifiable, durable identity for a persistent agent: a stable named entity with its own account, credentials and history rather than a disposable session.

Long-horizon goals

Long-horizon goals are objectives that an agent pursues autonomously over days, maintaining coherence across billions of tokens and many sub-tasks rather than completing one request and stopping.

Context rot

Context rot is the degradation of an AI agent's performance and memory reliability as its conversation history accumulates, even when the total stays within the model's nominal context window.

9 linksconcept

Memory poisoning

Memory poisoning is the compromise of a long-lived agent through its persistent context: a malicious email, document, calendar invite or retrieved record plants instructions or false facts that the agent carries forward into later actions.

6 linksconcept

On-device inference

On-device inference means running a language model on the user's own hardware, whether a laptop, a phone, a robot or an on-premise server, instead of calling a cloud API.
