IDE decline

first seen 2026-W36 · 6 links · 3 min read

The integrated development environment has been the engineer's primary workspace for decades. Inside OpenAI, IDE usage has been falling since January 2026 as engineers moved their work into Codex threads and, from July, into ChatGPT Work, while load on build, test and deploy systems rose roughly tenfold. The engineer now describes intent, reviews output and manages several agents rather than typing code line by line. Long-run observers of engineering practice list it among the largest shifts of the past five years, and treat it as emerging rather than settled.

For an executive, the change affects tooling spend, since editor and IDE licences lose value while harness and inference budgets grow; hiring, since the skill that matters shifts from fluency in an editor to judgement about specifications and review; and infrastructure, since the same shift moves load from the engineer's laptop to shared CI and deployment systems that were not sized for it.

Deeper dive

What is happening. The unit of work is moving from the editor buffer to the agent thread. In a Coding harness such as Codex, the engineer states a task, the agent edits, runs tests and opens a pull request, and the engineer reviews. Inside OpenAI, IDE usage has been falling since January as Codex absorbed the typing, and from July ChatGPT Work absorbed more of the surrounding tasks. The shift showed up in infrastructure as well: build, test and deploy systems saw roughly ten times their previous load, because agents iterate far more often than humans do.

Why now. Agents crossed the threshold where they can complete most routine changes end to end, and the harness became a better place to supervise them than an editor with an assistant bolted on. Once a team runs several agents in parallel, the editor is the wrong abstraction: it shows one file, while the work is many threads. That is the organisational form described as the Software factory, and Loop engineering is the practice of running it. Vibe coding is the consumer edge of the same shift, where the user never sees the code at all.

Trade-offs. Engineers who stop reading code closely lose the tacit knowledge that catches subtle bugs, and review quality depends on judgement the editor used to train. Tool vendors face a business-model question: the IDE was the point of sale for developer tooling, and the harness is now where the value concentrates. Infrastructure teams inherit the load. And measurement gets harder: IDE telemetry was the proxy for engineering activity, and it now undercounts.

What to watch. Whether IDE usage falls outside the labs at the same rate. Whether IDE makers rebuild their products around agent threads or cede the ground. And whether CI and deployment systems scale to agent cadence or become the next bottleneck.

Related terms

technique

Coding harness

A coding harness is the software layer wrapped around a language model that turns it into a working coding agent: the loop that manages context, calls tools, runs tests and decides what to do next.

needed by 9 · 28 linksproduct

Codex

Codex is OpenAI's coding agent, available as a command-line tool and a cloud service, that gives a GPT model file, shell and tool access so it can carry out engineering tasks end to end.

needed by 2 · 15 linksconcept

Software factory

A software factory is a production system in which agents run the reproduce, fix, review and verify loop end to end, with humans setting the rules and reviewing a fraction of the output.

needed by 1 · 17 linkstechnique

Loop engineering

Loop engineering is the practice of designing systems in which an AI agent prompts, executes, tests and verifies its own work repeatedly until a stopping condition is met, so that the human designs the loop rather than writing the code inside it.

needed by 1 · 8 linksconcept

Vibe coding

Vibe coding is building software by prompting a coding agent and accepting what it produces without understanding the stack, vendors or architecture it chose.
