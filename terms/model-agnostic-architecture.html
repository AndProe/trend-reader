Model-agnostic architecture

first seen 2026-W32 · 7 links · 3 min read

A model-agnostic product treats the model as a replaceable component behind a stable interface. The harness, tools, prompts and evaluation stay the same while the model underneath can be swapped for a cheaper, newer or better-suited one. Coding harnesses are the clearest case: one agent framework works across multiple providers, a major software vendor runs a single multi-model harness across its developer, security and productivity products, and even a lab's own coding agent now supports other providers' models.

For an executive the term is a procurement principle and a business-model warning at once. As a principle, keeping a model-agnostic layer preserves bargaining power and lets a company follow price and capability as they shift. As a business model, building a company on reselling many labs' models is fragile: the labs control access, pricing and the newest capabilities, and can withdraw any of them. The stance in the vault is that the swap-any-backend ideal survives mainly in coding tools and is declining as a standalone business.

Also seen as model-agnostic harness, pluggable backends, multi-provider platforms

Deeper dive

How it works. A model-agnostic architecture separates three layers: the application or harness that holds tools, prompts, memory and evaluation; a routing layer that selects a model per request; and the model providers themselves, accessed through a common interface. Swapping a model then means changing configuration rather than code, and Smart model routing can send each task to the cheapest model that meets its bar. In coding, this pattern is the norm: a Coding harness built to work across many underlying models, a single multi-model harness spanning a vendor's developer tools with model choice exposed to users, and a lab's coding agent that supports rival models.

Why it matters now. The forces pulling against it are strong. Access rationing means labs restrict their strongest models to trusted programmes and their own products, so a multi-provider platform never gets the frontier. Vertical integration of AI labs means the labs increasingly build the applications themselves, competing with the platforms that resell them. A hardware-standard proposal from one lab claims to be model-agnostic while all its examples use that lab's own model, which shows how thin the neutrality can be. The debate over whether any single AI company can dominate long term, by analogy with earlier general-purpose technologies, is the same question from the other side: if the answer is no, agnosticism is the right bet; if yes, it is a transitional state.

Trade-offs. Agnosticism costs capability. The best results often come from a model used with its own lab's tools, caches and features, and an abstraction layer either hides those or leaks. Cache affinity is a concrete example: an agent mid-task is tied to the model whose cache it has built. The layer also carries an engineering cost that a single-vendor product avoids. Against that, the state of Lab consolidation, which has been predicted and has not arrived, favours buyers who keep their options open.

What to watch. Whether lab coding agents keep supporting rival models, whether multi-provider platforms find durable margins, and how enterprise procurement policies treat single-vendor lock-in as the labs integrate downward.

Coding harness

A coding harness is the software layer wrapped around a language model that turns it into a working coding agent: the loop that manages context, calls tools, runs tests and decides what to do next.

Smart model routing

Smart model routing sends each request to the cheapest model that can handle it, reserving frontier models for the steps that need them and often running a small local model as the dispatcher.

Lab consolidation

Lab consolidation is the expected shake-out of the frontier model market to a handful of labs and, on the buyer side, one or two vendors per enterprise workload.

Access rationing

Access rationing is the practice of labs and governments deciding who may use the strongest AI models, through model withdrawals from distrusted platforms, gated frontier tiers, nationality screening and trusted-partner programmes.

Vertical integration of AI labs

Vertical integration of AI labs is model developers extending from models into the layers around them: buying developer toolchains, owning coding harnesses, moving into consumer verticals and cutting off third-party platforms.
