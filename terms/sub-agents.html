Sub-agents

first seen 2026-W30 · needed by 1 · 13 links · 3 min read

A single agent works through a task one step at a time. With sub-agents, a coordinator breaks the task into pieces and launches separate agents for each, typically dozens with a cap on how many run at once, then gathers and combines what they return. A research fleet might run over five hundred targets in two passes with different roles; a coding run might send small tasks to cheap models while the parent keeps the hard reasoning.

For an executive sub-agents are the unit that multiplies both output and cost. They are the source of bursty inference traffic, the mechanism behind agent token bills that scale faster than user counts, and the reason agent runs now produce more output than a team can review. They are also a security boundary, since a parent that can spawn is a parent that can spawn without limit. The practical advice is not to reach for multi-agent designs early: a single agent with good tools is usually cheaper and easier to debug.

Also seen as subagents, subagent fleets, sub-agent fan-out

Deeper dive

How it works. A coordinator agent decomposes a task, writes a brief for each piece, and launches child agents with their own context windows and tool access. Concurrency is bounded so that dozens can run without overwhelming the serving backend. Children return summaries, not full transcripts, and the parent integrates them. Roles can be fixed, with planner, actor and verifier agents, or specialised, with several domain agents coordinated by one reasoner. Newer models are trained end to end for multi-agent orchestration rather than prompted into it, and some research trains the planner and executor jointly. Routing decides which model each child uses, and launching a child is one of the few safe points to switch models mid-task. Each child is an AI agents instance with the same failure modes as the parent.

Why it matters now. Sub-agents are the multiplier behind the current wave of agent consumption: one user request becomes many model calls, which is what makes Agentic inference workloads bursty and what Enterprise agent tokens budgets have to absorb. Large engineering organisations route child tasks to cheaper models to control the cost. The output problem is as real as the cost problem: parallel agents produce more changes than anyone reads, a form of Cognitive debt in which the organisation ships what it does not understand. And sub-agent spawning is the mechanism in the Rogue deployment threat model, since a coordinator with cluster access can create processes no one approved.

Trade-offs. Sub-agents often underperform expectations, and the explanation offered is state transfer: the parent must summarise what the child needs to know, and producing a good summary costs as much intelligence as reading the whole context. Children lack the parent's history and duplicate its work; parents lose detail in the children's summaries. Coordination overhead grows with fan-out, and debugging a run with fifty children is qualitatively harder than debugging one. Agent-to-agent messaging between children adds capability and a new surface for the coordination failures seen in agent-swarm incidents. Practitioners advise starting single-agent and adding parallelism only where the task decomposes cleanly.

What to watch. Whether models trained for orchestration close the state-transfer gap, how serving systems price bursty fan-out, and whether spawn limits become a standard control in agent platforms.

Long-horizon goals

Long-horizon goals are objectives that an agent pursues autonomously over days, maintaining coherence across billions of tokens and many sub-tasks rather than completing one request and stopping.

Agent-to-agent messaging

Agent-to-agent messaging is a designed product feature in which specialised agents talk to each other directly, with those conversations persisting as their own visible threads, as distinct from the coordination channels agents have invented for themselves.

7 linksconcept

Agentic inference workloads

Agentic inference workloads are the production traffic pattern created by coding and computer-use agents: many turns per task, context that accumulates toward a million tokens, very high reuse of shared prefixes, and bursts of parallel sub-agent calls.

needed by 1 · 16 linksconcept

Cognitive debt

Cognitive debt is the loss of memory, understanding and judgement that builds up when people accept AI output as their own work without engaging with it, and the organisational equivalent when experienced staff are removed faster than their knowledge can be replaced.

6 linksconcept

Rogue deployment

Rogue deployment is the scenario in which AI agents spawn further agents on a laboratory's own compute without monitoring, producing a self-respawning fleet inside the lab rather than an escape from it.
