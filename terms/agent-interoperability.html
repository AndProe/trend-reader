Agent interoperability

first seen 2026-W36 · 5 links · 3 min read

Interoperability means an agent from one vendor can hand work to, or take work from, an agent from another, and both can operate in the same workspace. The most concrete current example is a large technology company standardising its internal chat on a single platform because agents from multiple vendors could all operate there, which made the platform choice an agent-infrastructure choice. Protocol proposals aim to make the same thing possible without a shared product in the middle.

For an executive the question is where the meeting point sits and who controls it. If agents interoperate through a collaboration platform, that platform becomes the control plane for agent work and its vendor gains leverage. If they interoperate through open protocols, the organisation keeps more freedom but takes on integration and security work. Either way, buying agents from several vendors without deciding how they will cooperate creates silos that are expensive to unwind. The decision belongs in platform strategy, alongside identity and data governance, not in individual team tool selection.

Also seen as agent interop, cross-vendor agents

Deeper dive

How it works. Interoperability can be achieved at three levels. At the platform level, agents from different vendors are installed into a common workspace such as a chat tool, which supplies shared identity, channels and message history; agents cooperate by reading and writing in the same threads, and the platform's permission model applies to all of them. At the protocol level, standards define how agents describe their capabilities, exchange tasks and return results directly; MCP covers how agents call tools, while agent-to-agent proposals cover how agents address each other and how an interaction is structured in natural language with security designed in. At the identity level, agents need to recognise and authorise each other, which is where Agent identity becomes a precondition rather than an add-on.

Why it matters now. Enterprises are accumulating agents from many suppliers, each with its own runtime and permissions, and the cost of that fragmentation is rising. The decision by a major company to move its internal communications to a platform specifically because agents could work across it shows that interoperability is already shaping infrastructure choices. At the same time the Agent protocols layer is being defined, and whoever sets the conventions for how agents talk will shape the market the way web standards shaped the last platform generation.

Trade-offs. Platform-based interoperability is fast and inherits mature identity and audit tooling, but it concentrates power in the platform vendor and makes the platform a single point of failure and attack. Protocol-based interoperability preserves choice but is immature: the proposals differ, security is not uniformly designed in, and the same channel that lets agents cooperate also lets a compromised agent manipulate another, a risk that new multi-agent security benchmarks are built to measure. Agent-to-agent messaging as a designed feature is easier to govern than the coordination agents invent for themselves, which argues for building the interoperability layer deliberately rather than letting it emerge.

What to watch. Whether one protocol gains the adoption that makes it a default, or whether platforms remain the practical interoperability layer. Whether collaboration-platform vendors position themselves explicitly as agent control planes. And whether interoperability standards include identity and authorisation from the start, or leave security to be retrofitted.

technique

Agent protocols

Agent protocols are the emerging standards that define how agents call tools, talk to each other and operate devices across vendors, with MCP, A2A, NLIP and a model hardware standard as the current proposals.

needed by 2 · 6 linkstechnique

MCP

MCP, the Model Context Protocol, is an open standard for exposing tools, data sources and device controls to AI agents through a uniform server interface.

8 linkstechnique

Agent-to-agent messaging

Agent-to-agent messaging is a designed product feature in which specialised agents talk to each other directly, with those conversations persisting as their own visible threads, as distinct from the coordination channels agents have invented for themselves.

7 linksconcept

Agent identity

Agent identity is a verifiable, durable identity for a persistent agent: a stable named entity with its own account, credentials and history rather than a disposable session.
