Developer tooling & practice

The software layer around a model: harnesses, routing and the practice of building agentic systems.

  1. technique

    Coding harness

    A raw language model can only answer prompts. A coding harness gives it hands: it feeds the model the right files, lets it run commands, captures the results, keeps the working context under control and loops until the task is done. Claude Code, Codex, Cursor and Devin are harnesses; so is Inspect, the in-house agent Ramp built on the open-source OpenCode harness. The same pattern is spreading beyond code into legal, customer-service and finance products, where the harness is the application and the model is an input.

  2. technique

    Verification loops

    A verification loop wraps an AI coding agent in automated checks: tests, linters, type checks, regression suites, trace replays or live interaction, plus a rule to retry until the checks pass. The agent proposes, the pipeline validates, and only validated changes proceed. Practitioners reporting large throughput gains attribute them to these loops rather than to any particular model, and organisations that migrated large codebases with AI describe the same retry-and-validate structure.

    Read the term →
  3. product

    Codex

    Codex is OpenAI's answer to the coding-agent category: a program that takes a task description, works through a codebase on its own, runs tests and returns a change ready for review. It runs either locally as a command-line tool or in OpenAI's cloud, and it is the direct rival to Anthropic's Claude Code. Each lab's models favour its own agent, so choosing Codex is in practice choosing GPT.

    Read the term →
  4. concept

    Software factory

    In a software factory the unit of work is not a developer with an assistant but a pipeline: an issue arrives, an agent reproduces it, another proposes a fix, a third reviews, a fourth verifies with the original reporter, and the result is merged if it passes the gates humans defined. At Vercel this accounts for twenty-five to thirty-five percent of merged pull requests; one lab runs a nine-stage agentic pipeline for its own code; and one company runs under rules that no human writes or reviews code, the dark-factory extreme.

    Read the term →
  5. technique

    Harness engineering

    A harness is everything wrapped around a model call: the system prompt, the tools it can invoke, the sandbox it runs in, how results are checked, when a human is asked, and how failures are retried. Harness engineering is the discipline of building that layer well. It sits on an abstraction ladder that runs from prompting a model, to designing its harness, to engineering the loops that run it, to factories that run many loops. Empirical studies now treat harness design as the unit of improvement: the same model scores very differently depending on the harness.

    Read the term →
  6. technique

    Observability

    Observability means being able to ask a running system what happened and get an answer. Traditional practice collected logs, metrics and traces separately; the current approach records one wide event per unit of work, rich with context, and derives everything else from it. For agents, the unit of work is a run that may last hours and spawn sub-runs, so the telemetry becomes traces of traces, and auto-instrumentation makes capturing it easier than not capturing it.

    Read the term →
  7. technique

    Code review

    Code review is the step where a colleague reads a proposed change, questions it and approves or rejects it before it enters the shared codebase. It has served as a quality check, a knowledge-sharing ritual and a control on risk. Coding agents have broken the assumption underneath it: when one engineer can produce ten times the changes, the reviewers become the bottleneck and the ritual either slows delivery or degrades into rubber-stamping.

    Read the term →
  8. technique

    Loop engineering

    Loop engineering means building a cycle rather than a one-shot request. An agent is given a goal, a way to act, a way to check its result and a rule for when to stop; it then runs on its own, fixing what the check rejects. Examples include an implementer loop that works through a ticket queue, a daily loop that proposes architecture improvements, and research methods that evolve an agent's training environment in the same iterative way.

    Read the term →
  9. concept

    Vibe coding

    Vibe coding is software by conversation: describe what you want, let the agent write it, run it, and keep prompting until it works. It has spread from hobbyists to marketing teams opening pull requests, in-house portals built in a day, and firms claiming hand-written code has ended for professional work. Labs use the phrase themselves for voice-driven app building.

    Read the term →
  10. concept

    Agentic engineering

    In agentic engineering the division of labour is explicit. Agents write every line, run tests and lint, and increasingly do exploration, specification and test construction. Engineers design the system, set constraints, write specifications that include how the agent should check its own work, and review outputs. Some companies now state as policy that nearly all their code is agent-generated, and the label extends to specialised domains such as production inference serving.

    Read the term →
  11. concept

    AI-assisted migrations

    AI-assisted migrations apply coding agents to the least glamorous work in software: moving a code base from one framework, language version or test library to another. Such migrations were deferred for years because they consumed senior engineers on repetitive changes across thousands of files. Case studies from Asana, Airbnb, Uber, Bun and Sentry describe agents doing the bulk of that work, with pipelines that attempt a change, run the tests, and retry until it passes.

    Read the term →
  12. technique

    Automated software maintenance

    Most engineering effort in an established company goes to keeping existing software working rather than building new features: patching bugs, upgrading libraries, paying down shortcuts taken years ago, and restructuring systems that have outgrown their design. Automated maintenance hands this work to agents that run continuously or on demand, produce changes, and submit them for review. Companies experimenting with it report results better than expected, with the caveat that agent-produced changes still need a person to review before they merge.

    Read the term →
  13. product

    Claude Code

    Claude Code is a program that runs in a developer's terminal and hands a Claude model the ability to read and edit files, execute commands, run tests and call other tools. The developer describes a task; the agent works through it in a loop and returns with changes ready for review. Unlike an autocomplete plug-in, it operates on the whole repository and takes stack and architecture decisions on the user's behalf, and is often described as building the whole application rather than assisting with parts of it.

    Read the term →
  14. technique

    TDD

    Test-driven development (TDD) reverses the usual order of work: the engineer writes a small automated test that fails, then writes just enough code to make it pass, then tidies up and repeats. The test is the specification, and a green test suite is the evidence that the code does what was asked.

    Read the term →
  15. technique

    AI code review

    AI code review puts a model in the reviewer's seat. It reads a diff, checks it against coding standards and security rules, flags tautological tests and questionable logic, and either comments or blocks the merge. The current practice runs several reviewers per change, sometimes different models and sometimes agents specialised by domain, after an implementer agent has produced the code.

    Read the term →
  16. concept

    Package registry

    A package registry is the shared store that every modern software project draws on. When a developer or an AI coding agent needs a library, the package manager fetches it from the registry, along with everything that library itself depends on. A handful of registries therefore sit underneath most of the world's software, run largely by volunteers and foundations rather than by the companies that rely on them.

    Read the term →
  17. technique

    AI incident response

    AI incident response puts an agent alongside the on-call engineer rather than in place of them. When an alert fires, the agent pulls logs, traces, recent deployments and similar past incidents into one summary, proposes mitigations, and in more advanced setups turns a production alert into a proposed code fix. The engineer decides. OpenAI's internal tooling is the reference case: an incident agent that gathers context and proposes without executing, and a pipeline that converts performance alerts into candidate fixes.

    Read the term →
  18. technique

    Remote sandboxes

    A remote sandbox is a disposable computer in the cloud that exists for the duration of one agent task. The agent gets a file system, a shell, network access within limits and the tools it needs; when the task ends the machine is discarded. Instead of one agent on a developer's laptop, a team can run dozens in parallel, each in its own box, configured centrally and driven from a chat client or a web interface.

    Read the term →
  19. technique

    Software performance

    Performance engineering is the work of making software fast. Two approaches exist. Hotspot optimisation profiles a running system, finds the few functions consuming most of the time and fixes them. Architectural performance designs the system from the start so that data flows efficiently. The argument gaining ground is that hotspot fixes only work when the architecture allowed for speed in the first place; a system built without regard for performance cannot be profiled into being fast.

    Read the term →
  20. concept

    Database schema

    A database schema is the rulebook that says what data an application stores and how it is shaped. Application code is written against it, so a change to the schema is a change to the contract that every part of the system relies on. Adding a column is usually safe; renaming or removing one can break code that still expects the old shape.

    Read the term →
  21. technique

    Model-agnostic architecture

    A model-agnostic product treats the model as a replaceable component behind a stable interface. The harness, tools, prompts and evaluation stay the same while the model underneath can be swapped for a cheaper, newer or better-suited one. Coding harnesses are the clearest case: one agent framework works across multiple providers, a major software vendor runs a single multi-model harness across its developer, security and productivity products, and even a lab's own coding agent now supports other providers' models.

    Read the term →
  22. product

    Bun

    Bun is a JavaScript runtime and toolchain that competes with Node.js by doing several jobs in one program: it runs code, installs packages, bundles applications and runs tests, and it does each of them noticeably faster than the incumbent tools. It was built from scratch with performance as the primary design goal rather than added as a layer on top of existing tooling.

    Read the term →
  23. concept

    GitHub reliability

    GitHub reliability refers to the run of outages on the platform since mid-2026. The cause is load: traffic roughly doubled in four months as coding agents began committing, opening pull requests and running checks continuously, and pull-request volume grew about fivefold. The same surge sits behind the strain on code review, since humans cannot read what agents produce at this rate.

    Read the term →
  24. product

    OpenTelemetry

    OpenTelemetry, usually shortened to OTel, is a shared specification and set of libraries for recording what a system does: which requests came in, how long each step took, what errors occurred and how services called one another. Because the format is open, the data can be sent to any monitoring vendor, and because auto-instrumentation hooks into popular web frameworks and database drivers, most of the telemetry arrives without developers writing extra code.

    Read the term →
  25. product

    Rust

    Rust is a programming language designed to run as fast as C and C++ while preventing the memory errors that cause most security vulnerabilities in those languages. Its compiler refuses code that could corrupt memory, which makes it slower to write but removes a whole category of production failures. It has grown from an enthusiast language to a default choice for infrastructure, command-line tools and performance-sensitive services.
