Evaluation & benchmarks

How model and agent capability is measured, and where common benchmarks understate or overstate it.

  1. technique

    Benchmarks

    Every model release opens with a benchmark table: the vendor's scores on a chosen set of tests, usually with competitors named only by tier. Independent scoreboards re-run models under common conditions, and researchers publish new suites weekly, increasingly with constructed ground truth, deterministic controls or generated question sets that renew forever to avoid contamination. Reviewers reproduce vendor claims with caveats, and the more useful reading has shifted from rank to cost-versus-score plots.

    Read the term →
  2. technique

    Agent benchmarks

    An agent benchmark gives a model a goal and an environment, lets it take many actions with tools, and scores the outcome. Examples in current use include SWE-bench Verified for fixing real software issues, Terminal-Bench for command-line work, AppWorld for multi-application tasks, ARC-AGI-3 and game environments for general problem solving, τ-Voice and EVA-Bench for voice agents, and newer suites for healthcare records, production serving, multilingual settings and agent security. Research groups now publish several new suites a week.

    Read the term →
  3. concept

    Alignment evaluation

    Capability benchmarks ask whether a model can complete a task. Alignment evaluation asks whether it will do what its developers want when it could do otherwise: whether it deceives evaluators, games its reward, sabotages tasks, hides its reasoning, or behaves differently when it believes it is being tested. Methods include automated audits, scripted scenarios, monitoring of reasoning traces, interpretability probes and resampling behaviour across varied environments. Safety institutes and civil society run parts of it, and one lab has piloted double-blind evaluations.

  4. metric

    Cost per task

    Model vendors quote prices per million tokens and publish benchmark scores. Neither tells a buyer what it costs to get a job done. A cheaper model that uses three times as many tokens, retries more often or needs a higher reasoning setting can cost more per finished task than an expensive one. Cost per task fixes the unit: dollars per resolved ticket, per merged pull request, per classified case or per completed benchmark item, at a stated accuracy. It has moved from an analyst's preferred metric to the axis the labs themselves now use in their launch charts.

    Read the term →
  5. technique

    Internal benchmarks

    Internal benchmarks, usually just called evals, are the tests a company writes for its own use of AI. Where a unit test checks deterministic code, an eval checks non-deterministic model behaviour against a set of cases drawn from the company's real work, with thresholds the company sets. They are run when a new model is considered, when prompts or tools change, and increasingly on every release of an agent.

    Read the term →
  6. product

    SWE-bench Verified

    SWE-bench takes real bug reports and feature requests from popular open-source Python projects, hands the agent the repository, and checks whether the agent's patch makes the project's tests pass. The Verified subset is the portion that human reviewers confirmed to be solvable and fairly specified, removing tasks with ambiguous descriptions or broken tests. A score is the percentage of issues resolved.

    Read the term →
  7. product

    Terminal-Bench

    Terminal-Bench is a test suite for coding agents that operate in a terminal. Each task gives the agent a shell, a goal and a working environment, and scores whether the end state is correct. Version 2.1 has 87 tasks and is small enough to run in full, which is why recent research reports complete runs rather than samples.

    Read the term →
  8. concept

    Benchmaxxing

    Benchmaxxing is the deliberate optimisation of a model for the public benchmarks that appear in launch tables. Labs know which test sets reviewers and buyers look at, and they shape training data and post-training so the model performs well on those sets. This is distinct from fraud: no one is falsifying numbers. It is closer to teaching to the exam, and every lab does some of it.

    Read the term →
  9. metric

    Token efficiency

    Token efficiency asks how much work a model gets done per token. Two models can rank similarly on capability while one produces far more output to reach the same answer, and agentic workloads consume roughly thirty input tokens for every output token, so the total bill depends on verbosity, context handling and reasoning effort as much as on the price per million tokens.

    Read the term →
  10. concept

    Causal grader

    Most automated tests of AI agents are acausal: they compare the final output to an expected answer and do not care how it was produced. A causal grader instead inspects the transcript, the tool calls and the intermediate work, and marks a correct answer as failed if it was obtained by cheating, such as reading the answer from a file the agent should not have opened.

    Read the term →
  11. technique

    Deployment qualification

    Deployment qualification asks a different question from a benchmark. Instead of how often the agent gets the right answer on a test set, it asks whether the agent plus its human oversight arrangement meets a stated reliability target on the actual task, with statistical confidence, before anyone depends on it. A related metric counts only completions that are acceptable in context, rather than all completions that happen to match a label.

    Read the term →
  12. product

    GDPval

    GDPval measures a model's performance on tasks drawn from real occupations: documents, analyses, spreadsheets and other deliverables of the kind knowledge workers produce, judged against expert-quality outputs and reported as an Elo rating. Unlike a coding benchmark, it is meant to approximate the work of the broader economy rather than of engineers.

    Read the term →
  13. product

    CyberGym

    CyberGym measures whether an AI agent can do offensive security work end to end: take a real codebase, locate a vulnerability, and produce a working exploit that is verified rather than self-reported. Scores are published on a leaderboard, which turns a hard-to-observe capability into a single comparable number.

    Read the term →
  14. product

    Artificial Analysis index

    The index is an independent scoreboard that runs a fixed set of evaluations against each released model and publishes a combined score, a ranking and a cost-per-index-point figure, with separate indexes for speech-to-speech quality and transcription accuracy. Because no lab produces it, it is the number cited when a vendor's own table is disputed: a five-point jump into first place, a fifth place at 46, or an open model with 18 billion active parameters matching a much larger closed one. Labs cite it for their own latency and error-rate claims.

    Read the term →
  15. product

    ARC-AGI-3

    ARC-AGI-3 tests interactive reasoning: rather than answering questions, a system is dropped into a game whose rules it has not seen and must infer them from play. GPT-6 Astra's reported result was a step change on the previous state of the art, and the benchmark's designer described it that way. The detail that drew attention was the harness. On the official harness the model scored 62.7 percent at about $26,000 of compute; on OpenAI's own continuous "Provider Adapter" harness it reported 99.9 percent at about $19,000, roughly $360 a game, using fewer actions than the human baseline on 96 percent of levels.

    Read the term →
  16. technique

    LLM-as-judge

    LLM-as-judge means asking a model to grade another model's work. Instead of paying human raters to read every answer, an evaluator writes a rubric, hands the output and rubric to a model, and takes the score it returns. Panels of several models, often from different families and run blind, are used to reduce the bias of any single grader.

    Read the term →
  17. product

    OSWorld

    OSWorld gives an agent a real operating system with real applications and asks it to complete tasks that span several of them: edit a spreadsheet, move data into a document, change a setting. Scores are checked programmatically. The benchmark launched in 2024 with agents near 12 percent, and by mid-2026 the best agents reached the low-to-mid 80s against a human baseline of roughly 72 percent. A stricter second version, OSWorld 2.0, is now the primary reference, with a partial and a strict score.

    Read the term →
  18. product

    InferenceX

    InferenceX runs the same models and serving stacks across competing hardware and reports tokens per second, cost per token and latency along the full curve from bulk throughput to high interactivity. AgentX does the same for agent workloads, which have different traffic patterns: long contexts, many short turns and heavy cache reuse. Recent rounds covered six Nvidia SKUs and AMD's MI355X, added Google's TPUv7, integrated power measurement, and served as the harness for experiments such as running accelerators with reduced HBM.

    Read the term →
  19. product

    ExploitBench

    ExploitBench is a test suite for offensive cyber capability: an agent is given targets and scored on whether it produces working exploits. It appears in the security sections of release reviews for GPT-6 Astra as one of the numbers by which the model's cyber ability is judged.

    Read the term →
  20. metric

    Open model adoption metrics

    Open model adoption metrics answer a simple question: are open-weight models being used, and by whom. The raw signals are download counts from model hubs, the number of derivative fine-tunes built on a base model, token volumes routed through public inference gateways, the share of requests inside open coding tools, and surveys of which models companies run in production. Because download counts favour older and smaller models, the more careful versions normalise for time since release and model size so that a new large model can be compared fairly with a small model that has been available for a year.
